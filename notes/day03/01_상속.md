### 객체지향 언어의 특징 — OOP is A P.I.E

| 특성 | 내용 |
|---|---|
| **A**bstraction(추상화) | 현실의 객체를 추상화해서 클래스를 구성함 |
| **P**olymorphism(다형성) | 하나의 객체를 여러 가지 타입(형)으로 참조할 수 있음 |
| **I**nheritance(상속) | 부모 클래스의 자산을 물려받아 자식을 정의 → 코드 재사용 |
| **E**ncapsulation(데이터 은닉과 보호) | 데이터를 외부에 직접 노출하지 않고 메서드로 보호함 |

### 상속이란

- 기존(상위) 클래스의 자산(멤버)을 자식(하위) 클래스에서 **재사용**하기 위한 것
  - 상위 클래스의 **생성자와 초기화 블록은 상속하지 않음**
- 상위 클래스의 멤버를 물려받으므로 **코드 절감**
  - 상위 클래스 코드를 고치면 모든 하위 클래스에 적용 → **유지 보수성 향상**
- `extends` 키워드 사용

| 물려주는 쪽 | 물려받는 쪽 |
|---|---|
| 조상 클래스 | 자식 클래스 |
| 상위 클래스 | 하위 클래스 |
| 슈퍼 클래스 | 서브 클래스 |

```java
public class InheritTest {
    public static void main(String[] args) {
        SpiderMan sman = new SpiderMan();
        sman.name = "피터 파커";
        sman.eat();      // 피터 파커 식사
        sman.jump();     // 두 다리로 힘껏 점프
        sman.fireWeb();  // 거미줄 발사!
    }
}

class Person {
    String name;
    void eat() { System.out.println(name + " 식사"); }
    void jump() { System.out.println("두 다리로 힘껏 점프"); }
}

class SpiderMan extends Person {   // Person의 name, eat(), jump()를 물려받음
    boolean isSpider;
    void fireWeb() { System.out.println("거미줄 발사!"); }
}
```

- 교재 질문 "SpiderMan의 멤버는 몇 개일까?" → 자기 것(`isSpider`, `fireWeb()`) + Person에서 받은 것(`name`, `eat()`, `jump()`) + Object에서 받은 메서드들

### Object 클래스

- **모든 클래스의 조상** 클래스
  - `extends` 선언이 없는 클래스는 `extends Object`가 생략된 것
  - 따라서 모든 클래스에는 Object에 정의된 메서드가 있음

| Object의 메서드 | 교재 설명 |
|---|---|
| `toString()`, `equals()`, `hashCode()` | 대부분 클래스에서 재정의해서 사용 |
| `wait()`, `notify()`, `notifyAll()` | 주로 멀티 스레드 프로그래밍에서 사용 |
| `getClass()`, `clone()`, `finalize()` | — |

### 다양한 상속 관계

- 상속 관계는 **is a (kind of)** 관계라고 함
  - Person is a Object, SpiderMan is a Person

```
            Object
              │
            Person
          ┌───┴────┐
     SpiderMan   Employee
```

| 교재 질문 | 관계 |
|---|---|
| Person과 Employee | Employee is a Person (상속) |
| Object와 Employee | Employee is a Object (간접 상속) |
| Employee와 SpiderMan | 상속 관계 없음 (같은 조상을 둔 형제) |

### 단일 상속(Single Inheritance)

- 다중 상속은 여러 클래스의 기능을 물려받을 수 있지만 관계가 매우 복잡해짐
  - 같은 이름의 메서드가 두 상위 클래스에 모두 있으면 하위 클래스는 어느 것을 쓰나?

```
  Person          Spider
  jump()          jump()
     └──────┬──────┘
        SpiderMan       <- jump()는 누구 것? (자바는 불가)
```

- 자바는 **단일 상속만 지원**
  - 대신 **interface**와 **포함 관계(has a)**로 단점 극복

### 포함 관계(has a)

- 상속 외에 클래스를 재활용하는 방법
  - 2개 이상 클래스의 특성을 가져올 때 **하나는 상속, 나머지는 멤버 변수**로 처리
- UML에서 포함 관계는 실선 화살표로 표현
- Spider 코드를 고치면 SpiderMan에도 반영 → 유지 보수성 확보

```java
class SpiderMan2 extends Person {   // Person과는 is a
    Spider spider;                  // Spider와는 has a
    boolean isSpider;

    void fireWeb() {
        if (isSpider) {
            spider.fireWeb();
        } else {
            System.out.println("Person은 거미줄 발사 불가");
        }
    }
}
```

### 상속이냐 포함이냐

- 문법 문제가 아니라 **프로젝트 관점의 문제**

| 방법 | 판단 기준 | 예 |
|---|---|---|
| 상속 | is a 관계가 성립하는가 | SpiderMan **is a** Person |
| 포함 | has a 관계가 성립하는가 | SpiderMan **has a** Spider |

- "SpiderMan is a Spider"는 어색하므로 Spider는 포함으로 처리

### Sealed class (Java 17~)

- **봉인된 클래스** — 내가 지정한 특정 클래스에게만 상속 허락
- 상속 계층을 엄격히 제어
  - 프로그램 구조를 명확히 유지, 의도치 않은 상속으로 생기는 복잡성·혼란 방지
  - 역할·직무 분류가 명확해야 하는 개념에서 주로 사용
- 작성법
  - class(interface 포함)에 `sealed`를 붙이고, 상속(구현)을 허락할 클래스를 `permits` 뒤에 나열
  - `sealed`가 선언된 클래스는 `permits`가 반드시 필요
  - 허락받은 하위 클래스는 다음 중 하나를 꼭 붙임

| 키워드 | 의미 |
|---|---|
| `sealed` | 여전히 봉인됨 → 다시 `permits`로 하위 클래스 나열 필요 |
| `final` | 더 이상 상속받을 수 없음 |
| `non-sealed` | 봉인 해제 → 자유롭게 상속 가능 |

> 참고: 하위 클래스가 모두 같은 소스 파일 안에 있으면 `permits`를 생략할 수 있음(컴파일러가 추론). 다른 파일에 있을 때는 교재대로 `permits`가 필요함.

```
            sealed SealedStudyGroup
        ┌──────────┼──────────────┐
    final Algo  sealed Java   non-sealed CS
                    │              │
              final Spring      Network
```

```java
sealed class SealedStudyGroup permits Algo, CS, Java {
    public void study() {
        System.out.println("공부 공부 공부!!");
    }
}

final class Algo extends SealedStudyGroup {}                    // 더 이상 상속 불가
sealed class Java extends SealedStudyGroup permits Spring {}    // 봉인 상태로 상속
final class Spring extends Java {}
non-sealed class CS extends SealedStudyGroup {}                 // 이후 자유롭게 상속
class Network extends CS {}
```
