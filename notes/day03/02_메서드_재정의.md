### 메서드 오버라이딩(overriding)

- 조상 클래스에 정의된 메서드를 자식 클래스에서 **적합하게 수정**하는 것
- 상황: SpiderMan2가 Person에게 물려받은 `jump()`는 "두 다리로 힘껏 점프"뿐 → 거미 능력이 있을 때는 Spider의 `jump()`를 쓰고 싶음
  - `else`에 Person의 출력 문장을 그대로 다시 쓰면 코드 중복 → `super.jump()`로 해결

```java
public class OverrideTest {
    public static void main(String[] args) {
        SpiderMan2 sman = new SpiderMan2();
        sman.jump();     // 두 다리로 힘껏 점프
        sman.fireWeb();  // Person은 거미줄 발사 불가

        sman.isSpider = true;
        sman.jump();     // 키 * 1000만큼 엄청난 점프
        sman.fireWeb();  // 거미줄 발사
    }
}

class Person {
    String name;
    void jump() { System.out.println("두 다리로 힘껏 점프"); }
}

class Spider {
    void jump() { System.out.println("키 * 1000만큼 엄청난 점프"); }
    void fireWeb() { System.out.println("거미줄 발사"); }
}

class SpiderMan2 extends Person {       // Person is a, Spider has a
    Spider spider = new Spider();
    boolean isSpider;

    void fireWeb() {
        if (isSpider) {
            spider.fireWeb();
        } else {
            System.out.println("Person은 거미줄 발사 불가");
        }
    }

    @Override
    void jump() {
        if (isSpider) {
            spider.jump();   // 포함한 객체의 메서드
        } else {
            super.jump();    // 조상의 메서드 재사용
        }
    }
}
```

### 오버라이딩의 조건

- 메서드 **이름**이 같아야 함
- 매개변수의 **개수, 타입, 순서**가 같아야 함
- **리턴 타입**이 같아야 함
- **접근 제한자**는 부모보다 범위가 넓거나 같아야 함
- 조상보다 **더 큰 예외**를 던질 수 없음

> 참고: Java 5부터는 리턴 타입이 조상 메서드 리턴 타입의 **하위 타입**이어도 오버라이딩으로 인정됨(공변 반환 타입). 기본형 리턴은 완전히 같아야 함.

### super 키워드 — 조상 멤버 접근

- `this`로 자기 멤버에 접근하듯 `super`로 **조상 클래스 멤버**에 접근
- `super.메서드()`로 조상 메서드를 호출 → 조상 코드 재사용

| 호출 | 실행되는 것 |
|---|---|
| `this.jump()` | 지금 클래스(SpiderMan2)의 `jump()` |
| `super.jump()` | 조상(Person)의 `jump()` |
| `spider.jump()` | 포함한 Spider 객체의 `jump()` |

### 변수의 scope

- 변수는 사용된 위치에서 점점 넓혀 가며 **처음 만난 선언부**에 연결됨
  - 메서드 내부 → 해당 클래스 멤버 변수 → 조상 클래스 멤버 변수

```java
public class ScopeTest {
    public static void main(String[] args) {
        Child child = new Child();
        child.method();
    }
}

class Parent {
    String x = "parent";
}

class Child extends Parent {
    String x = "child";

    void method() {
        String x = "method";
        System.out.println("x : " + x);
        System.out.println("this.x : " + this.x);
        System.out.println("super.x : " + super.x);
    }
}
/* 출력
x : method
this.x : child
super.x : parent
*/
```

| 교재 질문 | `x` | `this.x` | `super.x` |
|---|---|---|---|
| 1. 현재 상태 | method | child | parent |
| 2. method의 x를 주석 | child | child | parent |
| 3. Child의 x를 주석 (method의 x는 그대로) | method | parent | parent |
| 2와 3을 모두 주석 | parent | parent | parent |

- Child에 `x`가 없으면 `this.x`도 조상까지 올라가 `parent`를 찾음

### super() — 조상 생성자 호출

- `this()`가 같은 클래스의 다른 생성자를 부르듯 **`super()`는 조상 클래스의 생성자**를 호출
  - 조상에 선언된 멤버는 조상 생성자에서 초기화 → 그것을 재활용
  - 자식 클래스 생성자에서는 **자식에 선언된 멤버만** 초기화
- `super()`는 자식 생성자의 **맨 첫 줄**에서만 호출 가능
  - 즉 생성자 첫 줄에는 `this()` 또는 `super()` 중 하나만 올 수 있음
- `this()`나 `super()`를 명시하지 않으면 **컴파일러가 `super()`를 삽입**
  - 결국 맨 위 Object까지 객체가 모두 만들어지는 구조

### 생성자 호출과 객체 생성의 단계

```java
public class ConstructorTest {
    public static void main(String[] args) {
        SpiderMan3 sman = new SpiderMan3("피터 파커");
        System.out.println(sman.name + ", " + sman.isSpider);
    }
}

class Spider {}

class Person2 {
    String name;

    Person2(String name) {
        // super();  // 컴파일러가 Object()의 호출을 삽입
        this.name = name;
        System.out.println("1. Person2(String)");
    }
}

class SpiderMan3 extends Person2 {
    Spider spider;
    boolean isSpider;

    SpiderMan3(String name, Spider spider, boolean isSpider) {
        super(name);                 // 조상 멤버는 조상 생성자가 초기화
        this.spider = spider;        // 자식 멤버만 여기서 초기화
        this.isSpider = isSpider;
        System.out.println("2. SpiderMan3(String, Spider, boolean)");
    }

    SpiderMan3(String name) {
        this(name, new Spider(), true);
        System.out.println("3. SpiderMan3(String)");
    }
}
/* 출력
1. Person2(String)
2. SpiderMan3(String, Spider, boolean)
3. SpiderMan3(String)
피터 파커, true
*/
```

- 호출은 아래에서 위로(`SpiderMan3(String)` → `this(...)` → `super(name)` → `Object()`), 본문 실행은 위에서 아래로 끝남
- 메모리 구조

```
 sman ─► 0x100  SpiderMan3 객체
         ┌──────────────────────────┐
         │ Object 영역               │
         ├──────────────────────────┤
         │ Person2 영역  name = "피터 파커"   <- super
         ├──────────────────────────┤
         │ SpiderMan3 영역            │   <- this
         │   spider   = 0x200 ──► Spider 객체
         │   isSpider = true          │
         └──────────────────────────┘
```

### Annotation

- 사전적 의미는 "주석" — **컴파일러, JVM, 프레임워크 등이 보는 주석**
- 소스 코드에 **메타 데이터**를 삽입하는 형태
  - 소스 코드에 붙여 놓은 라벨
  - 코드에 대한 정보 추가 → 소스 구조 변경, 환경 설정 정보 추가 등의 작업 진행

| 기본 annotation | 컴파일러에게 알리는 것 |
|---|---|
| `@Deprecated` | 해당 메서드가 deprecated 되었음 |
| `@Override` | override한 메서드임 → 반드시 super class에 선언된 메서드여야 함 |
| `@SuppressWarnings` | 사소한 warning은 신경 쓰지 말 것 |

```java
class P {
    void jump() {}
}

class Q extends P {
    @Override
    void jumpp() {}   // 컴파일 에러: method does not override or implement a method from a supertype
}
```

- `@Override`를 붙이면 이름 오타 같은 실수를 컴파일 단계에서 잡아 줌
