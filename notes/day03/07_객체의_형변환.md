### 메모리에 있는 것과 사용할 수 있는 것의 차이

- 메모리에 객체가 있더라도 **참조하는 변수의 타입**에 따라 접근할 수 있는 내용이 제한됨

```
 new SpiderMan() 객체
 ┌─────────────────────────────┐
 │ Object 고유 영역              │ equals(), toString()     <- Object obj 로 보이는 범위
 ├─────────────────────────────┤
 │ Person 고유 영역              │ name, jump()             <- Person person 으로 보이는 범위(+Object)
 ├─────────────────────────────┤
 │ SpiderMan 고유 영역           │ isSpider, fireWeb()      <- SpiderMan sman 으로 보이는 범위(전부)
 └─────────────────────────────┘
```

### 참조형 객체의 형 변환

| 방향 | 이름 | 기본형 예 | 참조형 예 | 생략 |
|---|---|---|---|---|
| 하위 → 상위 | **묵시적 캐스팅** | `int i = b;` (byte → int) | `Object obj = person;` | 가능 |
| 상위 → 하위 | **명시적 캐스팅** | `byte b = (byte) i;` | `SpiderMan sman = (SpiderMan) person;` | 불가 |

- 자손 타입 객체를 조상 타입으로 참조: 조상의 모든 내용이 자식에 있으므로 걱정할 필요 없음 → 생략 가능
- 조상 타입을 자손 타입으로 참조: 조상에는 자손의 기능이 없을 수 있음 → 생략 불가
  - 교재 비유: 부모는 마음이 넓어 모든 자식을 품지만, 자식은 부모를 품을 수 없음

### 무늬만 SpiderMan인 Person

```java
Person person = new Person();
SpiderMan sman = (SpiderMan) person;   // 컴파일은 됨
sman.fireWeb();
// Exception in thread "main" java.lang.ClassCastException: class Person cannot be cast to class SpiderMan
```

- 메모리의 객체(Person)에는 `fireWeb()`이 없음 → 실행 중 **ClassCastException**
- 조상을 무작정 자손으로 바꿀 수는 없음

### instanceof 연산자

- 실제 메모리에 있는 객체가 특정 클래스 타입인지 **boolean**으로 리턴
- Java 16부터는 검사와 형 변환을 한 번에 하는 **패턴 매칭** 사용 가능

```java
Person person = new Person();

// 기존 방식
if (person instanceof SpiderMan) {
    SpiderMan sman = (SpiderMan) person;
    sman.fireWeb();
}

// Java 16~ 패턴 매칭
if (person instanceof SpiderMan sman) {
    sman.fireWeb();
}
// person은 실제로 Person 객체라 두 if 모두 false → 실행 안 됨
```

```java
public class CastTest {
    public static void main(String[] args) {
        Person person = new SpiderMan();        // 묵시적 형 변환
        // person.fireWeb();                    // 컴파일 에러: Person 타입으로는 안 보임
        SpiderMan sman = (SpiderMan) person;    // 명시적 형 변환 — 실제 객체가 SpiderMan이라 안전
        sman.fireWeb();                         // 거미줄 발사

        Person onlyPerson = new Person();
        System.out.println(onlyPerson instanceof SpiderMan);  // false
    }
}

class Person {
    void jump() { System.out.println("두 다리로 힘껏 점프"); }
}

class SpiderMan extends Person {
    void fireWeb() { System.out.println("거미줄 발사"); }
}
```

## 정적 바인딩과 동적 바인딩

### 참조 변수의 레벨에 따른 객체의 멤버 연결

```java
public class MemberBindingTest {
    public static void main(String[] args) {
        SubClass subClass = new SubClass();
        System.out.println(subClass.x);    // sub
        subClass.method();                 // sub class method

        SuperClass superClass = subClass;
        System.out.println(superClass.x);  // super             <- 변수: 참조 타입 기준
        superClass.method();               // sub class method  <- 메서드: 실제 객체 기준
    }
}

class SuperClass {
    String x = "super";

    public void method() {
        System.out.println("super class method");
    }
}

class SubClass extends SuperClass {
    String x = "sub";

    @Override
    public void method() {
        System.out.println("sub class method");
    }
}
```

```
 new SubClass() 객체
 ┌──────────────────────────────────────────┐
 │ SuperClass 고유 영역  x = "super"           │ <- SuperClass superClass
 │                      method() (재정의됨)   │
 ├──────────────────────────────────────────┤
 │ SubClass 고유 영역    x = "sub"             │ <- SubClass subClass
 │                      method() → "sub class method"
 └──────────────────────────────────────────┘
```

| 구분 | 언제 결정 | 무엇으로 결정 | 대상 |
|---|---|---|---|
| **정적 바인딩**(static binding) | 컴파일 단계 | 참조 변수의 타입 | 상속 관계에서 중복된 멤버 변수(static/instance), static method |
| **동적 바인딩**(dynamic binding) | runtime | 메모리의 실제 객체 타입 | 재정의된 instance method → 마지막에 재정의된 자식 메서드 호출 |

- 최대한 메모리에 생성된 **실제 객체의 최적화된 메서드**가 동작함

### 객체가 출력되는 과정

- `System.out.print(spiderMan)` → 결국 **Object의 `toString()`** 때문에 출력됨

```
 PrintStream.print(Object obj)   → write(String.valueOf(obj))
 String.valueOf(Object obj)      → (obj == null) ? "null" : obj.toString()
 Object.toString()               → getClass().getName() + "@" + Integer.toHexString(hashCode())
```

```java
System.out.println(new Plain());   // Plain@6dde5c8c  (16진수 부분은 실행마다 다름)
```

- `toString()`을 재정의하면 동적 바인딩으로 **재정의된 메서드**가 호출됨 → 객체의 상태를 출력

```java
public class PrintObject {
    public static void main(String[] args) {
        Object member = new MemberInfo();
        System.out.println("객체 정보: " + member);  // 객체 정보: 이름: 홍길동, 등급: 정회원
    }
}

class UserInfo {
    String name = "홍길동";

    @Override
    public String toString() {
        return "이름: " + this.name;
    }
}

class MemberInfo extends UserInfo {
    String grade = "정회원";

    @Override
    public String toString() {
        return super.toString() + ", 등급: " + grade;   // 조상의 toString 재사용
    }
}
```

### 가장 적합한 파라미터 타입은?

- jump가 가능한 객체라면 jump하고 싶을 때, 메서드 파라미터를 어떤 타입으로 둘까

```java
public class AppropriateParameter {
    public void useJump1(Object obj) {
        if (obj instanceof Person casted) {
            casted.jump();
        }
    }

    public void useJump2(Person person) {
        person.jump();
    }

    public void useJump3(SpiderMan spiderMan) {
        spiderMan.jump();
    }

    public static void main(String[] args) {
        Object obj = new Object();
        Person person = new Person();
        SpiderMan sman = new SpiderMan();
        AppropriateParameter ap = new AppropriateParameter();

        ap.useJump1(obj);     // 호출은 되지만 실제로 jump할 수는 없음 (출력 없음)
        ap.useJump1(person);  // 두 다리로 힘껏 점프
        ap.useJump1(sman);    // 거미줄 타고 점프

        // ap.useJump2(obj);  // 컴파일 에러
        ap.useJump2(person);  // 두 다리로 힘껏 점프
        ap.useJump2(sman);    // 거미줄 타고 점프

        // ap.useJump3(obj);     // 컴파일 에러
        // ap.useJump3(person);  // 컴파일 에러
        ap.useJump3(sman);    // 거미줄 타고 점프
    }
}

class Person {
    void jump() { System.out.println("두 다리로 힘껏 점프"); }
}

class SpiderMan extends Person {
    @Override
    void jump() { System.out.println("거미줄 타고 점프"); }
}
```

| 파라미터 타입 | 받을 수 있는 것 | 특징 |
|---|---|---|
| `Object` | 모두 | 활용도는 가장 높지만 `instanceof` 검사·형 변환이 필요 → 코드 복잡 |
| `Person` | Person, SpiderMan | jump 가능한 객체만 받음, 검사 불필요 |
| `SpiderMan` | SpiderMan | 너무 좁음 |

- 상위 타입으로 올라갈수록 활용도는 높아지지만 **코드 복잡성도 증가**
- Java API처럼 공통 기능이면 Object를 파라미터로 쓰지만, 많은 경우 비즈니스 로직상 **그 기능을 가진 최상위 객체**(여기서는 Person)를 쓰는 게 좋음
