## 매핑 어노테이션 한눈에

| 대상 | 어노테이션 |
|---|---|
| 객체 ↔ 테이블 | `@Entity`, `@Table` |
| 필드 ↔ 컬럼 | `@Column`, `@Basic`, `@Enumerated`, `@Transient` |
| 기본 키 | `@Id`, `@GeneratedValue`, `@SequenceGenerator` |
| 연관관계 | `@ManyToOne`, `@OneToMany`, `@JoinColumn` → [연관관계 매핑 기초](03_연관관계_매핑_기초.md) |

- Hibernate 문서는 어노테이션을 두 층으로 나눔
  - **논리 층**: `@Entity`, `@Id`, `@Basic` — 자바 도메인 모델의 의미
  - **매핑 층**: `@Table`, `@Column` — DB 객체에 어떻게 대응하는지
  - 논리 층 → 매핑 층으로는 정보가 추론되지만 반대 방향은 없음

## 객체와 테이블 매핑

### @Entity
- 붙어야 JPA(스프링 부트)가 그 클래스를 **엔티티**로 인식 → 테이블과 매핑
- 엔티티 클래스 조건

| 조건 | 이유/비고 |
|---|---|
| 인자 없는 생성자(public 또는 protected) 필수 | JPA가 리플렉션으로 객체를 만듦. 다른 생성자 추가는 자유 |
| 클래스를 `final`로 선언 금지, 메서드·영속 필드도 `final` 금지 | |
| enum·인터페이스는 엔티티가 될 수 없음 | |
| 영속 필드는 private/protected/package 접근 | 외부는 getter나 비즈니스 메서드로 접근 |
| 기본 키(`@Id`) 필수 | 루트 엔티티에 정확히 한 번 |

- 매핑 어노테이션은 **필드에 일관되게** 붙임 → `@Id`가 필드에 있으면 필드 접근, getter에 있으면 프로퍼티 접근(요즘은 필드 접근이 일반적)

### @Table
- 엔티티와 매핑할 테이블 지정. 없으면 기본값 적용

| 속성 | 기본값 | 뜻 |
|---|---|---|
| `name` | 엔티티 이름 | 매핑할 테이블 이름 |
| `schema` / `catalog` | DB 기본값 | 스키마·카탈로그 |
| `uniqueConstraints` | 없음 | 테이블 유니크 제약 — **테이블 생성(DDL) 때만** 사용 |
| `indexes` | 없음 | 인덱스 — **테이블 생성 때만** 사용, PK 인덱스는 자동 |

```java
@Entity
@Table(name = "MEMBER")
public class Member { ... }
```

### 이름 규칙 (Spring Boot)
- Spring Boot 기본 물리 이름 전략 = `CamelCaseToUnderscoresNamingStrategy`
  - 카멜 케이스 → 언더스코어, 점(.) → 언더스코어, 테이블 이름은 소문자
  - `TelephoneNumber` 엔티티 → `telephone_number` 테이블, `createDate` 필드 → `create_date` 컬럼
- 바꾸려면 `spring.jpa.hibernate.naming.physical-strategy` / `implicit-strategy`

## 데이터베이스 스키마 자동 생성

### 개념
- 매핑 어노테이션에서 DB 스키마를 추론해 **애플리케이션 시작 시 테이블(DDL)을 자동 생성** → 엔티티를 기준으로 테이블이 만들어짐
- 테스트에서 특히 유용함. Jakarta EE 튜토리얼도 개발 단계용이지 운영 DB 대상 기능이 아니라고 설명

### Spring Boot: `spring.jpa.hibernate.ddl-auto`

| 값 | 동작 |
|---|---|
| `none` | 엔티티가 바뀌어도 DB를 건드리지 않음 |
| `validate` | 엔티티와 테이블이 맞는지 **검사만** 함 (변경 없음) |
| `update` | 엔티티에서 **바뀐 부분만** DB에 반영 (없는 것만 추가) |
| `create` | 시작할 때 기존 테이블을 모두 삭제하고 다시 생성 |
| `create-drop` | `create` + **종료할 때도** 테이블 삭제 |

- 기본값: **임베디드 DB(H2·HSQLDB·Derby)이고 Flyway·Liquibase가 없으면 `create-drop`**, 그 밖에는 `none`
  - 인메모리 DB에서 실제 DB로 바꿀 때 테이블이 자동으로 있을 거라고 가정하지 말고 `ddl-auto`를 명시해야 함
- 권장(위키독스): 개발 환경은 보통 `update`, **운영 환경은 `none` 또는 `validate`**
- `create`/`create-drop`으로 스키마를 새로 만들 때 클래스패스 루트의 `import.sql`이 실행됨 (Hibernate 기능)

### JPA 표준 속성으로는
- `jakarta.persistence.schema-generation.database.action` (순수 JPA `persistence.xml`에서)

| 값 | 동작 |
|---|---|
| `none` | 생성·삭제 안 함 (속성 미지정 시와 같음) |
| `create` | 생성만 (먼저 지우지 않음) |
| `drop-and-create` | 지우고 다시 생성 |
| `drop` | 삭제 |
| `create-drop` · `validate` · `update` | Hibernate가 추가로 지원하는 값 |

### DDL 생성 기능은 DDL에만 영향
- `@Column(nullable = false)`, `@Table(uniqueConstraints = ..., indexes = ...)` 같은 제약은 **DDL을 자동 생성할 때만** 반영됨 → 실행 중 JPA가 값을 검사하지는 않음
- 반면 `@Basic(optional = false)`는 논리 층이라 Hibernate가 **DB에 쓰기 전에 직접 검사**함
  - `optional=false`는 `nullable=false`를 포함하지만, 반대는 아님

## 필드와 컬럼 매핑

### 기본 동작
- 엔티티 필드는 `@Column`이 없어도 **컬럼으로 인식** (기본값 적용)
- 컬럼으로 만들고 싶지 않으면 `@Transient` (또는 자바 `transient` 키워드) → 클래스 안에서만 쓰는 값

### @Column 속성

| 속성 | 기본값 | 뜻 |
|---|---|---|
| `name` | 필드 이름 | 매핑할 컬럼 이름 |
| `nullable` | `true` | `false`면 DDL에 `not null` |
| `unique` | `false` | 한 컬럼짜리 유니크 제약 (여러 컬럼이면 `@Table(uniqueConstraints)`) |
| `length` | `255` | 문자열 컬럼 길이 |
| `columnDefinition` | 타입에서 추론 | DDL에 쓸 컬럼 정의 SQL 조각 직접 지정 (예: `"TEXT"`) |
| `insertable` / `updatable` | `true` | INSERT/UPDATE SQL에 이 컬럼을 넣을지 |
| `precision` / `scale` | `0` | `BigDecimal` 같은 소수 컬럼의 전체 자릿수 / 소수 자릿수 |
| `table` | 기본 테이블 | 컬럼이 있는 테이블 |

### 기본 타입 (`@Basic`)
- 기본형, 래퍼, `String`, `BigDecimal`·`BigInteger`, `java.time`(`LocalDate`, `LocalDateTime`, `Instant` 등), `byte[]`, `UUID`, enum 등은 자동으로 기본 타입 컬럼
- 날짜는 `java.util.Date`/`Calendar`(deprecated 취급) 대신 **`java.time`** 사용 권장 → 위키독스 예제도 `LocalDateTime createDate`
- 기본형(`int` 등) 필드는 기본으로 `NOT NULL`로 추론됨

### @Enumerated

| 설정 | 저장 값 |
|---|---|
| `@Enumerated` / 생략 (기본 `ORDINAL`) | enum 순서 숫자(`ordinal()`) |
| `@Enumerated(EnumType.STRING)` | enum 이름(`name()`) |

- Hibernate 문서: JPA 기본값(ORDINAL)은 잘못 고른 기본값 → 숫자는 의미를 알기 어려워 **대부분 `STRING` 권장**

### 위키독스 예제 — 질문 엔티티

```java
package com.mysite.sbb;

import java.time.LocalDateTime;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;

import lombok.Getter;
import lombok.Setter;

@Getter
@Setter
@Entity
public class Question {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;                 // 기본 키, DB가 자동 증가

    @Column(length = 200)
    private String subject;             // 길이 200

    @Column(columnDefinition = "TEXT")
    private String content;             // 길이 제한 없는 텍스트

    private LocalDateTime createDate;   // @Column 없어도 컬럼 → create_date
}
```

| 엔티티 속성 | 설명 |
|---|---|
| `id` | 질문 고유 번호 |
| `subject` | 제목 |
| `content` | 내용 |
| `createDate` | 작성 일시 |

- 서버를 재시작하면(`ddl-auto=update`) H2 콘솔에서 `QUESTION` 테이블이 생성된 것을 확인할 수 있음

### 여러 매핑을 모은 예

```java
import java.math.BigDecimal;
import java.time.LocalDateTime;

import jakarta.persistence.*;

@Entity
@Table(name = "MEMBER")
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false, length = 50)
    private String username;

    @Column(precision = 12, scale = 2)
    private BigDecimal balance;

    @Enumerated(EnumType.STRING)
    private RoleType roleType;

    @Column(updatable = false)
    private LocalDateTime createdAt;

    @Transient
    private String tempMessage;     // 컬럼으로 만들지 않음

    protected Member() {}
}

enum RoleType { USER, ADMIN }
```

## 기본 키 매핑

### 직접 할당 vs 자동 생성

| 방식 | 코드 | 언제 |
|---|---|---|
| **직접 할당** (자연 키) | `@Id`만 | 사용자에게 의미 있는 값(예: ISBN)이 PK일 때. 애플리케이션이 값을 넣어야 함 |
| **자동 생성** (대리 키) | `@Id @GeneratedValue` | 시스템이 생성. 스키마를 직접 정할 수 있다면 Hibernate 문서는 **대리 키 권장** (모델 변경·리팩터링이 쉬움) |

### @GeneratedValue 전략 (`GenerationType`)

| 전략 | 자바 타입 | 구현 |
|---|---|---|
| `IDENTITY` | `Long`/`Integer` | DB의 identity·`auto_increment`·`bigserial` 컬럼에 맡김 |
| `SEQUENCE` | `Long`/`Integer` | DB 시퀀스 사용 — `@SequenceGenerator`로 세부 지정 |
| `TABLE` | `Long`/`Integer` | 키 생성용 테이블 사용 — `@TableGenerator` |
| `UUID` | `UUID`/`String` | 자바에서 UUID 생성 |
| `AUTO` (**기본값**) | `Long`/`Integer` 등 | 식별자 타입과 DB 기능에 따라 SEQUENCE·TABLE·UUID 중 선택 |

```java
@Id @GeneratedValue                               // AUTO
Long id;

@Id @GeneratedValue(strategy = GenerationType.IDENTITY)
Long id;

@Id @GeneratedValue UUID id;                      // AUTO가 타입 보고 UUID 선택
```

### SEQUENCE 전략과 allocationSize

```java
@Id
@GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "bookSeq")
@SequenceGenerator(name = "bookSeq", sequenceName = "seq_book",
                   initialValue = 5, allocationSize = 10)
Long id;
```

```sql
-- 위 설정에 대응하는 시퀀스
create sequence seq_book start with 5 increment by 10
```

- `allocationSize`만큼 id를 **블록으로 미리 받아** 쓰고, 다 쓰면 그때 DB에 다시 요청 → 새 id마다 DB를 가지 않음
- 대신 생성된 id가 **연속되지 않을 수 있음**
- 스키마를 Hibernate 밖에서 관리하면 `initialValue`·`allocationSize`를 DDL의 `start with`·`increment by`와 맞춰야 함
- 제너레이터는 이름으로 여러 엔티티가 공유할 수 있음

### 기본 키 타입
- 기본형, 래퍼, `String`, `UUID`, `BigDecimal`, `BigInteger`, (`java.util.Date`/`java.sql.Date`) 가능
- **부동소수점 타입은 PK로 쓰지 않음**, 자동 생성 PK는 **정수 타입**만 이식성이 보장됨
- `@GeneratedValue`는 `@Id`가 붙은 속성에만 사용 가능
- 여러 컬럼 복합 키는 `@EmbeddedId` 또는 `@IdClass` (키 클래스는 `equals`/`hashCode` 구현, `Serializable` 필요)

## 참고

> 참고: 위키독스 2-04는 `strategy`를 생략하면 "모든 속성에 번호를 차례로 생성해 순서가 일정한 고유 번호를 가질 수 없다"고 설명함. 공식 문서 기준으로는 생략 시 기본값이 `GenerationType.AUTO`이고, Hibernate가 식별자 타입과 DB 기능에 따라 SEQUENCE·TABLE·UUID 중 하나를 고르는 것. 또 `@GeneratedValue`는 `@Id` 속성에만 붙일 수 있음.

- 위키독스는 엔티티에 Setter를 두지 말고 생성자와 변경용 메서드로 값을 다루는 쪽을 권함(예제는 편의상 Setter 사용)
- Hibernate 6에서 `@Enumerated(STRING)`은 대부분 DB에서 `CHECK` 제약이 붙은 `VARCHAR`, MySQL에서는 `ENUM` 컬럼으로 생성됨
- Spring Boot 문서는 현재 버전(4.x) 기준이지만 `ddl-auto` 값·기본값 규칙과 이름 전략은 3.x 설정과 같은 속성명을 씀

## 면접 포인트

- **`ddl-auto`는 운영에서 어떻게?** 운영에서는 `none` 또는 `validate`로 둠. `create`는 시작 때, `create-drop`은 시작·종료 때 테이블을 지우므로 운영 데이터가 사라짐 → 개발·테스트용.
- **`@Column(nullable=false)`와 `@Basic(optional=false)` 차이?** 앞은 DDL 생성 때 `not null` 제약만 만들고, 뒤는 Hibernate가 저장 전에 null을 직접 검사함. `optional=false`는 `nullable=false`를 포함함.
- **`@Enumerated` 기본값의 문제?** 기본 ORDINAL은 순서 숫자를 저장해 enum 순서가 바뀌면 데이터 의미가 틀어지고 읽기 어려움 → `EnumType.STRING` 사용.
- **IDENTITY와 SEQUENCE 차이?** IDENTITY는 DB의 auto_increment 컬럼에 키 생성을 맡기고, SEQUENCE는 DB 시퀀스에서 값을 받으며 `allocationSize`로 여러 개를 미리 받아 DB 왕복을 줄일 수 있음.
