## 출력 예측

### 출력 1 · static 변수와 참조 복사

```java
class Counter {
    static int total = 0;
    int count = 0;
    Counter() { total++; count++; }
}

// main
Counter a = new Counter();
Counter b = new Counter();
Counter c = b;
c.count += 10;
System.out.println(a.count + " " + b.count + " " + Counter.total);
```

**답**

```
1 11 2
```

- `new`는 **두 번**만 했다 → 객체는 a, b 두 개. 생성자가 2번 실행돼서 `total = 2`.
- `Counter c = b;`는 객체를 복사하는 게 아니라 **b의 주소를 c에 복사**한 것. c와 b는 같은 객체를 가리킨다.
- 그래서 `c.count += 10`은 곧 `b.count += 10` → b.count = 11.
- a는 별개의 객체라 count = 1 그대로.

```
[Static]         [Stack]           [Heap]
total = 2        a = 0x100  ──▶   0x100 { count: 1 }
                 b = 0x200  ──┐
                 c = 0x200  ──┴▶  0x200 { count: 11 }
```

### 출력 2 · call by value (배열)

```java
static void change(int[] arr, int n) {
    arr[0] = 99;
    n = 99;
    arr = new int[]{0, 0, 0};
    arr[1] = 99;
}

// main
int[] a = {1, 2, 3};
int n = 1;
change(a, n);
System.out.println(Arrays.toString(a) + " " + n);
```

**답**

```
[99, 2, 3] 1
```

한 줄씩 따라가면:

1. `arr[0] = 99` → arr에는 a와 **같은 주소**가 복사돼 있다 → 원본 배열이 `[99, 2, 3]`으로 바뀜 ✅
2. `n = 99` → 기본형이라 **복사본만** 바뀜. main의 n은 1 그대로
3. `arr = new int[]{0,0,0}` → 지역 변수 arr가 **새 배열**을 가리키게 됨. 이제 a와 연결 끊김
4. `arr[1] = 99` → 새 배열이 바뀔 뿐 원본 a와 무관

`CallByTest`의 change2(원본 바뀜)와 change3(주소를 바꾸면 원본 그대로)를 한 메서드에 합친 문제다.

### 출력 3 · this() 생성자 호출 순서

```java
class Box {
    int w, h;
    Box() { this(1); System.out.print("A"); }
    Box(int s) { this(s, s); System.out.print("B"); }
    Box(int w, int h) { this.w = w; this.h = h; System.out.print("C"); }
}

// main
Box b = new Box();
System.out.println(" " + b.w * b.h);
```

**답**

```
CBA 1
```

`this(...)`는 생성자의 첫 줄이라 **먼저 끝까지 내려간 다음** 돌아오면서 나머지 줄을 실행한다.

```
Box()          → this(1) 호출, 아직 A 출력 안 함
  Box(1)       → this(1, 1) 호출, 아직 B 출력 안 함
    Box(1, 1)  → w=1, h=1, "C" 출력 ← 제일 먼저
  돌아와서     → "B" 출력
돌아와서       → "A" 출력
```

- 마지막 줄: `*`가 `+`보다 먼저 → `" " + 1` → `" 1"`

## 버그 찾기

### 버그 1 · 이름이 저장되지 않음

```java
class Member {
    String name;
    Member(String name) {
        name = name;
    }
}

System.out.println(new Member("규").name);   // null 출력
```

**문제점**

- 생성자 안에서 `name`은 **파라미터 name**을 가리킨다 (가까운 쪽이 우선).
- `name = name;`은 파라미터에 파라미터를 다시 넣는 것 → 멤버 변수는 기본값 `null` 그대로.

**수정:** `this.name = name;`

### 버그 2 · 컴파일 에러

```java
public class Calc {
    int add(int a, int b) { return a + b; }

    public static void main(String[] args) {
        System.out.println(add(1, 2));
    }
}
```

**문제점**

- `main`은 static → 객체 없이 실행된다.
- `add`는 인스턴스 메서드 → **객체가 있어야** 호출 가능.
- static 안에서는 "어떤 객체의 add인지" 알 수 없어서 에러.

**수정 (둘 중 하나)**

- `static int add(int a, int b)` → add가 객체 값을 안 쓰니까 static이 자연스럽다
- `new Calc().add(1, 2)` → 객체를 만들어서 호출

## 빈칸 채우기

### 빈칸 1 · 두 점 거리의 제곱

```java
int distSq(Point other) {
    int dx = this.x - other.x;
    int dy = this.y - other.y;
    return dx * dx + dy * dy;
}
```

- `this`는 메서드를 호출한 점, `other`는 넘겨받은 점.
- `p1.distSq(p2)`라면 this = p1, other = p2.
- `this.`는 생략 가능 (`x - other.x`). 파라미터와 이름이 안 겹치니까.

### 빈칸 2 · 회원 번호 자동 발급

```java
private static int nextId = 1;
private final int id;

Member() {
    this.id = nextId++;
}
```

- `nextId++` (후위 증가) → **현재 값을 먼저 id에 넣고** 그다음 nextId가 1 증가.
- nextId는 **static**이라 모든 Member가 하나를 공유 → 1, 2, 3 순서로 발급된다.
- id는 **인스턴스 변수**라 객체마다 따로 → 각 회원이 자기 번호를 가진다.
- `final`이라 한 번 정해지면 못 바꾼다.

| new 순서 | id에 들어간 값 | 그 후 nextId |
|---|---|---|
| 1번째 | 1 | 2 |
| 2번째 | 2 | 3 |
| 3번째 | 3 | 4 |

## 핵심 정리

| 함정 | 기억할 것 |
|---|---|
| `c = b` | 객체 복사가 아니라 **주소 복사** → 같은 객체를 두 변수가 가리킴 |
| static 변수 | 클래스당 1개, 모든 객체가 공유 (`total`, `nextId`) |
| 메서드에 배열 넘기기 | 내용 수정은 원본에 반영, **변수에 새 배열 대입**은 원본과 무관 |
| 기본형 파라미터 | 복사본만 바뀜 |
| `this(...)` | 가장 안쪽 생성자부터 끝나고 바깥으로 돌아옴 |
| `name = name` | 파라미터끼리 대입 → 반드시 `this.name = name` |
| static에서 인스턴스 메서드 | 바로 호출 불가 → static으로 바꾸거나 객체 생성 |
| `nextId++` | 현재 값 쓰고 나서 증가 (후위) |
