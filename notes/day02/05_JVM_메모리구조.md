## JVM (Java Virtual Machine)

- 자바 프로그램이 실행되는 **환경 제공**
- 메모리를 체계적으로 관리하기 위해 **여러 영역으로 나뉨**
  - 메서드 영역 (Method Area)
  - 힙 영역 (Heap Area)
  - 스택 영역 (Stack Area)
  - PC 레지스터 (PC Register)
  - 네이티브 메서드 스택 (Native Method Stack)
- **GC** (Garbage Collection) : JVM이 가비지 컬렉터로 메모리를 자동 관리 — 사용되지 않는 객체를 메모리에서 해제

## JVM 메모리 구조 — 런타임 데이터 영역

> JVM 버전에 따라 달라질 수 있음

```
┌──────────────────────── 런타임 데이터 영역 ────────────────────────┐
│  ┌────────────────────┐   ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  │ 메서드 영역         │   │ 스택 영역 │ │ PC       │ │ 네이티브  │   │
│  │  └ 런타임 상수 풀   │   │          │ │ 레지스터 │ │ 메서드   │   │
│  ├────────────────────┤   │          │ │          │ │ 스택     │   │
│  │ 힙 영역             │   │          │ │          │ │          │   │
│  └────────────────────┘   └──────────┘ └──────────┘ └──────────┘   │
│     모든 스레드가 공유              스레드마다 생성                    │
└────────────────────────────────────────────────────────────────────┘
```

### 메서드 영역 (Method Area)

- **클래스 정보**를 저장하는 영역
- 정적 변수, 상수, 메서드 등이 저장됨
- 일부 JVM에 따라 GC가 관리해 주는 경우도 있음
- **모든 스레드가 공유**
- **클래스 로더**(Class Loader)에 의해 클래스가 로드될 때 저장되는 공간
- 비유 → 회사의 매뉴얼(설계도) / 지침

### 힙 영역 (Heap Area)

- **객체 인스턴스**를 저장하는 공간
- **GC가 관리**하는 영역 (사용되지 않는 객체를 자동 삭제)
- 인스턴스 변수, 배열 등이 저장
- 애플리케이션이 사용할 수 있는 **가장 큰 메모리**
- **모든 스레드가 공유**
- **문자열 상수 풀** 관리 (Java 7+)
- 비유 → 프로젝트 자료 같은 것들

### 스택 영역 (Stack Area)

- **지역 변수**, 메서드 호출 시 사용되는 값, 연산 결과 등 저장
- 메서드 호출 시 **스택 프레임**이 생성되고, 끝나면 스택 프레임 제거
- 접시를 쌓듯 쌓이는 형태
- **스레드마다 생성**
- 비유 → 작업 중인 문서 or 책상 (곧 치워질 예정)

### PC 레지스터 (Program Counter Register)

- 현재 실행 중인 **메모리의 주소**를 저장하는 영역
- 프로그램 **실행 흐름을 제어**하는 데 사용
- **스레드마다 생성**
- 비유 → 지금 하고 있는 작업 위치

### 네이티브 메서드 스택 (Native Method Stack)

- **네이티브 언어(C, C++ 등)**로 작성된 메서드 호출 시 사용하는 메모리 영역
- **스레드마다 생성**
- 비유 → 외주 업체와 협업

### 영역별 정리

| 영역 | 저장 내용 | 공유 | 비유 |
|---|---|---|---|
| 메서드 영역 | 클래스 정보, 정적 변수, 상수, 메서드 (+ 런타임 상수 풀) | 모든 스레드 | 회사 매뉴얼 |
| 힙 영역 | 객체 인스턴스, 인스턴스 변수, 배열, 문자열 상수 풀 | 모든 스레드 | 프로젝트 자료 |
| 스택 영역 | 지역 변수, 호출 시 값, 연산 결과 (스택 프레임) | 스레드마다 | 작업 중인 책상 |
| PC 레지스터 | 현재 실행 중인 주소 | 스레드마다 | 지금 작업 위치 |
| 네이티브 메서드 스택 | C/C++ 메서드 호출용 | 스레드마다 | 외주 업체 |

## 객체 생성과 메모리 할당

```java
public class MemoryTest {
    public static void main(String[] args) {
        Person p1 = new Person();
        p1.name = "김싸피";
        p1.age = 35;
        p1.hobby = "유튜브";
        p1.info();                                  // 김싸피 35 유튜브

        Person p2 = new Person();
        p2.name = "박싸피";
        p2.age = 25;
        p2.hobby = "유튜브";
        p2.info();                                  // 박싸피 25 유튜브

        System.out.println(p1 == p2);               // false
        System.out.println(p1.hobby == p2.hobby);   // true
    }
}

class Person {
    String name;
    int age;
    String hobby;

    void info() {
        System.out.println(name + " " + age + " " + hobby);
    }
}
```

```
메서드 영역(클래스 영역)        스택 영역                      힙 영역
-----------------------        ---------                      -------
Person                         [p1.info]  (호출 끝나면 제거)   p1 객체
 - name, age, hobby            [MemoryTest.main]                name  : 0x100 ──> "김싸피"
 - info()                        Person p1 ──> p1 객체          age   : 35
MemoryTest                       Person p2 ──> p2 객체          hobby : 0x200 ──> "유튜브"
 - main()                                                     p2 객체
                                                                name  : 0x300 ──> "박싸피"
                                                                age   : 25
                                                                hobby : 0x200   (같은 "유튜브" 공유)
```

- 클래스 정보(필드 목록, 메서드)는 **메서드 영역**에 한 번만
- `p1`, `p2` 참조 변수는 `main`의 **스택 프레임**에, 실제 객체는 **힙**에
- `p1.info()` 호출 시 `info` 프레임이 스택에 쌓였다가 끝나면 제거
- 두 객체의 `hobby`는 같은 문자열 리터럴 `"유튜브"`를 가리킴(문자열 상수 풀) → `p1.hobby == p2.hobby`가 `true`
- 객체 자체는 서로 다름 → `p1 == p2`는 `false`
