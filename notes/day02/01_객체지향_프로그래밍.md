## OOP

### 객체지향 언어의 특징 — OOP is A P.I.E

| 특성 | 내용 |
|---|---|
| **Abstraction** (추상화) | 현실의 객체를 추상화해서 클래스를 구성 |
| **Polymorphism** (다형성) | 하나의 객체를 여러 가지 타입(형)으로 참조 가능 |
| **Inheritance** (상속) | 부모 클래스의 자산을 물려받아 자식을 정의 → 코드 재사용 |
| **Encapsulation** (데이터 은닉과 보호) | 데이터를 외부에 직접 노출하지 않고 메서드로 보호 |

## 객체지향 프로그래밍

### 객체지향 프로그래밍이란? — Object Oriented Programming

- **객체**(客體) : 주체가 아닌 것, 주체가 활용하는 것
  - 우리 주변의 모든 것이 프로그래밍 대상 — 사물, 개념, 논리 …
  - 현실 생활 자체가 객체지향
- **객체지향 프로그래밍** : 주변의 많은 것들을 객체화해서 프로그래밍하는 것
- 예) 서울의 김모씨가 부산의 최모양에게 꽃을 선물하려면?
  - 직접 경작·직접 배달할 필요 없이 **꽃집 객체**에 주문(주소·상품 전달)
  - 꽃집은 기존 **택배사 객체**(택배 시스템)를 **재사용**해 배송
  - 택배사가 마음에 안 들면 다른 택배사로 **교체**하면 됨

```
서울 김모씨 --주문(주소:부산, 상품:장미)--> [꽃집] --요청--> [택배사] --배송--> 부산 최모양
                                                    (기존 택배 시스템 재사용 / 맘에 안 들면 교체)
```

### 객체지향 프로그래밍의 장점

- **블록 형태의 모듈화된 프로그래밍**
  - 신뢰성 높은 프로그래밍 가능
  - 추가/수정/삭제가 용이
  - 재사용성이 높음
- 블록 ↔ 객체 비유 : 검증된 크기·색상·모양을 가진 블록을 끼우기·빼기·움직이기로 조립
- 객체지향 or not — "날개만 수정하고 싶다면?", "하늘을 날게 하고 싶다면?" 같은 변경을 생각해 보면 모듈화의 차이가 드러남

## Class vs Object

### 현실 세계 객체, 클래스, 프로그램의 객체(instance, object)의 관계

- 현실 객체가 갖는 **속성과 기능**은 **추상화**(abstraction)되어 **클래스**(class)에 정의됨
- 클래스는 **구체화**되어 프로그램의 **객체**(instance, object)가 됨
- 현실의 객체 = 만지고 느낄 수 있는 것, 실생활에 구체화되어 있는 것
- 객체를 필요할 때마다 처음부터 새로 만들어야 한다면? → 실생활에서는 **설계도·틀** 사용
  - 설계도 자체는 쓰지 않고, 설계도로 만든 제품을 사용
  - 설계도 = 하나의 종류(**Type**), 설계도로 나온 제품 = **객체**, 객체는 주체가 사용
- 붕어빵 틀 = Type 규정 / 붕어빵 = 객체

### 추상화와 구체화

```
현실세계 객체                 클래스 (추상화)              프로그램 객체 (구체화)
--------------                ----------------             ----------------------
철수: 이름 철수, 나이 27   ->  class Person {           ->  Person p = new Person();
영희: 이름 영희, 나이 25         String name;    // 멤버변수     p.name = "철수";
상태/속성: 이름, 나이, 배고픔    int age;                       p.age = 20;
기능/행위: 먹는다, 일한다        boolean isHungry;              p.isHungry = false;
                                 void eat()      // 멤버메서드  p.eat();
                                 void work()                    p.work();
                               }
```

| 현실 | 클래스 | 객체 |
|---|---|---|
| 상태, 속성 | 멤버 변수 | 객체마다 다른 값 |
| 기능, 행위 | 멤버 메서드 | `객체.메서드()` 호출 |

### Try Yourself — 추상화로 클래스 만들고 구체화로 객체 사용하기

- `Person.java` : 앞의 정의로 Person 클래스 작성
- `PersonTest.java` : Person 타입으로 객체 2개 생성·사용
- 객체들은 모두 클래스에 선언된 속성을 가지지만, **객체별로 다른 상태 값**을 가짐

```java
// Person.java
public class Person {
    String name;
    int age;
    boolean isHungry;

    void eat() {
        System.out.println("냠냠.");
        isHungry = false;
    }

    void work() {
        System.out.println("열심히");
        isHungry = true;
    }
}
```

```java
// PersonTest.java — Person을 객체화해서 사용하는 주체
public class PersonTest {
    public static void main(String[] args) {
        Person person1 = new Person();
        person1.name = "홍길동";
        person1.isHungry = true;
        System.out.println(person1.name + " : " + person1.isHungry); // 홍길동 : true
        person1.eat();                                                 // 냠냠.
        System.out.println(person1.name + " : " + person1.isHungry); // 홍길동 : false

        Person person2 = new Person();
        person2.name = "임꺽정";
        person2.isHungry = true;
        System.out.println(person2.name + " : " + person2.isHungry); // 임꺽정 : true
        System.out.println(person1.name + " : " + person1.isHungry); // 홍길동 : false
    }
}
```

### 객체 생성과 메모리 — JVM의 메모리 구조

> JVM 버전에 따라 달라질 수 있음

| 영역 | 저장 내용 | 특징 |
|---|---|---|
| **meta-space** | 클래스 정보 처리 — 타입 정보, Field 정보, Method 정보, 상수 풀 | |
| **heap** | 객체를 저장하기 위한 영역 | thread에 의해 공유 / 객체가 생성되고 **G.C**에 의해 정리됨 |
| **stack** | 메서드들의 실행 공간 | **thread별로 별도 관리** / 메서드 호출 시마다 메서드 프레임 적층 / 메서드 프레임에 로컬 변수도 쌓임 |

```
 스레드 1          스레드 2
 [stack]           [stack]          [heap]               [meta-space]
 변수 a            변수 a'          객체  객체  객체       클래스 정보
 변수 b            변수 b'          (모든 스레드가 공유)    클래스 정보
```

### 객체의 생성과 메모리 할당

- 위 `PersonTest.main` 실행 시 메모리 모습 (주소는 예시)

```
meta-space                  stack                         heap
-----------                 -----                         ----
Person                      [p1.eat]          (실행 후 제거)
 - name, age, isHungry      [PersonTest.main]             0x100 : Person
 - eat(), work()              Person p1 = 0x100              name     = 0x200 ("홍길동")
PersonTest                    Person p2 = 0x300              age      = 0
 - main()                                                    isHungry = true -> false (eat 후)
                                                          0x300 : Person
                                                             name     = 0x400 ("임꺽정")
                                                             age      = 0
                                                             isHungry = true
```

- `new Person()` 직후 멤버 변수는 기본값(`null`, `0`, `false`)으로 시작 → 대입문으로 값 변경
- 참조 변수 `p1`, `p2`는 stack에, 실제 객체는 heap에 있음 → p1, p2는 **서로 다른 객체**를 가리킴
