## 메서드 정의와 필요성

### 메서드란?

- 현실 객체가 하는 **동작을 프로그래밍화**
- 어떤 작업을 수행하는 **명령문의 집합**

### 메서드를 작성하는 이유

- 반복적으로 사용되는 **코드의 중복 방지**
  - **DRY** : Don't Repeat Yourself
  - **WET** : We Enjoy Typing / Write Everything Twice
- 코드의 양을 줄이고 유지보수가 용이

### 메서드로 모듈화하기

- 메서드 없이 출력 : 객체마다 `System.out.println(p.name + ":" + p.age);` 반복
  - `name`, `age`가 `myName`, `myAge`로 바뀌면 출력하는 모든 곳을 고쳐야 함
- Person에 `printInfo()`를 추가하면 → **한 군데만 변경**, Person 객체가 일을 하니 주체 코드가 간단해짐

```java
class Person {
    String name;
    int age = 0;

    void printInfo() {
        System.out.println(name + " : " + age);
    }
}
```

```java
Person p = new Person();
Person p2 = new Person();
p.printInfo();
p2.printInfo();
```

## 선언부

### 리턴 타입

- 메서드를 호출한 곳으로 반환되는 값의 타입, 아무것도 리턴하지 않으면 **`void`**
- 결과를 받을 때 **묵시적 형 변환** 적용
- 리턴 타입은 **하나만** 가능 → 여러 데이터를 넘기려면? (배열·객체로 묶어서 반환)

```java
public int add(int a, int b) {
    return a + b;
}

public void sayHello() {
    System.out.println("Hello");
}
```

```java
int result1 = add(100, 200);     // 300
double result2 = add(100, 200);  // 300.0 (int -> double 묵시적 형변환)
// System.out.println(sayHello()); // 컴파일 오류: void는 값이 없음
```

### 메서드 이름 / 파라미터 목록

- 메서드 이름은 수행하는 작업을 쉽게 파악하도록 **의미 있는 이름** 사용
- 파라미터 목록 : 호출 시점에 넘겨줘야 하는 변수들, 넘겨줄 정보가 없으면 생략 가능
- 파라미터 전달 시에도 **묵시적 형변환** 적용

```java
public long add(long a, long b) {
    return a + b;
}

add(100, 200);   // (O) int -> long 자동 변환
add(1.1, 2.2);   // (X) double -> long 자동 변환 불가, 컴파일 오류
```

## Variable arguments

- 동일 타입 인자가 몇 개 들어올지 예상할 수 없을 때(가변적)
  - 배열 타입으로 선언할 수 있지만 → 호출 전 배열을 생성·초기화해야 하는 번거로움
  - **`...`**으로 파라미터를 선언하면 넘겨준 값의 개수에 맞춰 **자동으로 배열 생성 및 초기화**

```java
public class VariableTest {
    public void addAll(int... params) {   // params는 int[]
        int sum = 0;
        for (int i : params) {
            sum += i;
        }
        System.out.println(sum);
    }

    public static void main(String[] args) {
        VariableTest vt = new VariableTest();
        vt.addAll(1, 2, 3);        // 6
        vt.addAll(1, 2, 3, 4, 5);  // 15
        vt.addAll(1, 2);           // 3
    }
}
```

- Variable arguments가 적용된 대표 메서드 : `printf`

```java
public PrintStream printf(String format, Object ... args) {
    return format(format, args);
}
```

## 구현부

- 중괄호 안에 처리할 내용, 즉 **비즈니스 로직** 작성
- 동작의 마지막에 선언된 리턴 타입에 해당하는 값을 **`return`**과 함께 반환
  - 값 반환 시 묵시적 형 변환 적용
  - 리턴 타입이 `void`면 `return` 생략 가능
- 조건문으로 return할 경우 **모든 조건에서 return 필요**

```java
public double calc(double a, double b, char oper) {
    if (oper == '+') {
        return a + b;
    } else if (oper == '-') {
        return a - b;
    } else {
        return 0;          // else가 없으면 컴파일 오류(missing return)
    }
}

public double calc2(double a, double b, char oper) {
    double result = 0;
    if (oper == '+') {
        result = a + b;
    } else if (oper == '-') {
        result = a - b;
    }
    return result;         // 마지막에 한 번만 return
}
```

```java
calc(3, 1, '-');   // 2.0
calc2(3, 1, '*');  // 0.0
```

## class 멤버와 instance 멤버 간의 참조와 호출

- 가장 중요한 것 : **호출하려는 멤버가 메모리에 있는가?**
  - 메모리에 있으면 호출 가능
  - 메모리에 없으면 호출 불가 — 먼저 메모리에 로딩 후 사용
- **static member** → 언제나 메모리에 있음 (클래스 로딩 시 자동 등록)
- **instance member** → 객체 생성 전에는 메모리에 없음
  - 객체 생성 시 모든 instance 멤버가 메모리에 생성
  - 객체, 즉 레퍼런스를 통해서 접근

| 비고 | static member | non static member (instance member) |
|---|---|---|
| 소속 | 클래스 | 객체 |
| 같은 클래스에서 | 바로 호출 | 바로 호출 (단, static 메서드 안에서는 객체 생성 후) |
| 다른 클래스에서 | `클래스_이름.멤버_이름` | 객체 생성 후 `객체_이름.멤버_이름` |

### 연습 — 번호별로 호출하는 코드는?

```java
public class First {
    static int cv;                  // ①
    int iv;                         // ②

    static void cMethodA() {        // ③  ①, ④ 호출
        cv = 100;
        cMethodB();
    }

    static void cMethodB() {        // ④  ②, ⑤ 호출 -> static이라 객체 생성 필요
        First f = new First();
        f.iv = 10;
        f.iMethodA();
    }

    void iMethodA() {}              // ⑤

    void iMethodB() {               // ⑥  ②, ⑤ 호출 -> 같은 객체 멤버라 바로
        iv = 100;
        iMethodA();
    }

    void iMethodC() {               // ⑦  ⑨, ⑩ 호출 -> 다른 클래스
        Second.cMethod();
        Second s = new Second();
        s.iMethod();
    }

    void iMethodD(Second s) {       // ⑧  ⑨, ⑩ 호출 -> 받은 참조 s 사용
        Second.cMethod();
        s.iMethod();
    }
}

class Second {
    static void cMethod() {}        // ⑨
    void iMethod() {}               // ⑩
}
```

| 질문 | 교재 보기 |
|---|---|
| ③에서 ①, ④ | ⓑ `cv = 100; cMethodB();` |
| ④에서 ②, ⑤ | ⓒ `First f = new First(); f.iv = 10; f.iMethodA();` |
| ⑤에서 ①, ③ | ⓔ `cv = 100; cMethodA();` |
| ⑥에서 ②, ⑤ | ⓓ `iv = 100; iMethodA();` |
| ⑦에서 ⑨, ⑩ | ⓕ `Second.cMethod(); Second s = new Second(); s.iMethod();` |
| ⑧에서 ⑨, ⑩ | ⓐ `Second.cMethod(); s.iMethod();` |

> 짝 맞추기는 교재 보기를 규칙대로 풀어 본 것

## 메서드 호출 스택

- **스택**(stack) : First In Last Out 구조
- **메서드 호출 스택**
  - 메서드 호출마다 메서드 동작을 위한 **메모리 상자(프레임)**를 하나씩 할당
  - 상자 안에 파라미터 변수 등 로컬 변수 구성
  - A 메서드에서 B 호출 → B를 위한 상자를 위에 쌓음
  - 언제나 **맨 위 상자(B)만 활성화**, A는 끝나지 않고 잠시 정지
  - B가 리턴하면 B 상자 제거·메모리 반납 → A가 다시 최상위가 되어 동작 재개

```
 aMethod 호출       bMethod 호출        bMethod 리턴
 ------------       ------------        ------------
                    [bMethod] 동작 중
 [aMethod] age=10   [aMethod] 일시정지  [aMethod] age=10 재시작
 [main] args={}     [main] args={}      [main] args={}
```

## 기본형 변수와 참조형 변수

- 메서드 호출 시 파라미터로 입력된 **값을 복사해서 전달**
- Java는 **call by value** — 그럼 value의 정체는?
  - 기본형 : 값 자체가 복사 → 메서드 안에서 바꿔도 원본 그대로
  - 참조형 : **참조값(주소)**이 복사 → 같은 객체를 가리키므로 객체의 멤버를 바꾸면 원본 객체가 바뀜

```java
public class CallByTest {
    int memberVar = 10;

    static void change1(int var) {
        var += 10;
        System.out.printf("change1 : %d%n", var);
    }

    static void change2(CallByTest cbt1) {
        cbt1.memberVar += 100;
        System.out.printf("change2 : %d%n", cbt1.memberVar);
    }

    public static void main(String[] args) {
        CallByTest cbt = new CallByTest();
        cbt.memberVar = 5;
        System.out.printf("change1 호출 전 memberVar: %d%n", cbt.memberVar); // 5
        change1(cbt.memberVar);                                              // change1 : 15
        System.out.printf("change1 호출 후 memberVar: %d%n", cbt.memberVar); // 5
        change2(cbt);                                                        // change2 : 105
        System.out.printf("change2 호출 후 memberVar: %d%n", cbt.memberVar); // 105
    }
}
```

```
change1(cbt.memberVar)              change2(cbt)
  var = 5 (값 복사)                   cbt1 = 0x100 (참조값 복사)
  var += 10 -> 15                     cbt  = 0x100 ─┐
  원본 memberVar = 5 그대로                          └─> [0x100] memberVar 5 -> 105
```

## 메서드 오버로딩

### overloading : 동일한 기능을 수행하는 메서드의 추가 작성

- 일반적으로 메서드 이름은 기능별로 의미 있게 정함
- 동일한 기능을 여러 형태로 정의해야 한다면?
  - `eatUsingChopsticks`, `eatUsingFork`, `eatUsingSpoon` vs `eat(chopsticks)`, `eat(fork)`, `eat(spoon)`
  - 입으로 이동하는 부분까지만 다르고 그 이후 동작은 같음

### println 메서드 고찰

- `System.out.println(1)`, `println('C')`, `println("Hi")` — 뭐든 출력할 때는 println
- 사실은 모두 다른 메서드 : `println(int x)`, `println(char x)`, `println(String x)`
- 모두 다른 이름(`printlnInt`, `printlnChar`, `printlnString`)이었다면 피곤했을 것
- **장점** : 기억해야 할 메서드 감소, 중복 코드의 효율적 관리

### 메서드 오버로딩 방법

- **메서드 이름은 동일**
- **파라미터의 개수 또는 순서, 타입이 달라야 함** — 파라미터가 같으면 중복 선언 오류
- **리턴 타입은 의미 없음**

| 경우 | 코드 | 결과 |
|---|---|---|
| 파라미터 이름만 다름 | `int add(int a, int b)` / `int add(int x, int y)` | 오류 (중복) |
| 리턴 타입만 다름 | `int add(int a, int b)` / `long add(int a, int b)` | 오류 (중복) |
| 파라미터 타입이 다름 | `long add(int a, int b)` / `long add(long a, long b)` | 오버로딩 O |

### 메서드 오버로딩의 예 — 중복 코드 제거

- Person의 `walk`를 다양하게 오버로딩 → 하는 일이 같으므로 **가장 구체적인 메서드 하나에 위임**

```java
// 중복 있는 버전: 세 메서드가 각자 출력
void walk() {
    System.out.println("100cm 이동");
}
void walk(double distance) {
    System.out.println(distance + "cm 이동");
}
```

```java
// 중복 제거 버전: 짧은 쪽이 긴 쪽을 호출
void walk() {
    walk(100, "cm");
}

void walk(double distance) {
    walk(distance, "cm");
}

void walk(double distance, String unit) {
    distance = switch (unit) {          // switch 식 (Java 14+)
        case "cm" -> distance;
        case "inch" -> distance * 2.54;
        default -> {
            System.out.println("unknown");
            yield 0;
        }
    };
    System.out.println(distance + "cm 이동");
}
```

```java
p.walk();            // 100.0cm 이동
p.walk(30);          // 30.0cm 이동
p.walk(10, "inch");  // 25.4cm 이동
p.walk(10, "feet");  // unknown
                     // 0.0cm 이동
```
