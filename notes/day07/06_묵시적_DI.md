## 3. 묵시적 DI

### 묵시적 DI

- 명시적 DI처럼 `@Configuration` 클래스에서 `@Bean`을 쓰지 **않는** 형태
- **@Component**: 빈으로 사용할 **각 클래스에** 직접 표시

```java
@Target(ElementType.TYPE)
public @interface Component {
    String value() default "";   // 생성되는 빈의 이름을 재정의하려는 경우 사용
}
```

- 기본 빈 이름
  - 클래스 이름이 **Pascal case**면 첫 글자만 소문자로 바꾼 **camel case**
  - 그렇지 않으면(앞 두 글자가 대문자 등) **클래스 이름 그대로**
  - `@Component`의 `value` 속성으로 재정의 가능

| 클래스 | 기본 빈 이름 |
|---|---|
| `IronMan` (Pascal case) | `ironMan` |
| `SWasher` (Pascal case 아님) | `SWasher` |

### @Autowired

- **빈을 주입**하기 위해 사용하는 annotation

```java
@Target({ElementType.CONSTRUCTOR, ElementType.METHOD,
         ElementType.PARAMETER, ElementType.FIELD,
         ElementType.ANNOTATION_TYPE})
public @interface Autowired {
    boolean required() default true;
}
```

- **타입 기반**으로 빈을 자동 주입 → 해당 타입의 빈은 반드시 **하나만** 있어야 함
  - 타입 충돌이 나면 이름 조건을 추가하는 **@Qualifier** 활용
- 생성자·메서드에 쓰면 대상 파라미터는 모두 **Spring Bean** 또는 `@Value`로 받는 **scalar 값**
  - scalar: 복합 객체나 컬렉션이 아닌 단일 값
- 한 클래스에서 `@Autowired`를 붙인 **생성자는 최대 하나**, 메서드는 여러 개 가능
- 생성자가 **1개**면 당연히 그 생성자가 호출되므로 `@Autowired` **생략 가능**

### @ComponentScan

- `@Component`는 "빈이 될 수 있다"는 **의도**일 뿐, 실제로 빈을 만들지 않음
- `@ComponentScan`으로 대상을 **scan**해야 빈으로 등록됨
- `@Configuration`이 선언된 클래스에 사용

```java
@Target(ElementType.TYPE)
public @interface ComponentScan {
    @AliasFor("basePackages")
    String[] value() default {};
    @AliasFor("value")
    String[] basePackages() default {};   // @Component를 찾아볼 package 등록 - 하위 패키지 모두 scan
}
```

- `basePackages`로 scan 대상 패키지 등록
  - 생략하면 이 annotation이 붙은 **클래스의 패키지와 그 하위 패키지**를 scan

### 테스트 (TODO: 06)

- `@ExtendWith(SpringExtension.class)`: JUnit과 Spring을 연결 → 테스트 클래스에서 `@Autowired` 사용 가능
- `@ContextConfiguration(classes = ...)`: 사용할 설정 파일 등록

```java
@ExtendWith(SpringExtension.class)            // JUnit과 Spring 연결
@ContextConfiguration(classes = BagConfig.class)  // 설정 파일 등록
public class BagTest {
    @Autowired
    Bag bag;

    @Test
    public void bagTest() {
        Assertions.assertNotNull(bag);
    }
}
/* 결과
Caused by: org.springframework.beans.factory.NoUniqueBeanDefinitionException:
  No qualifying bean of type 'com….Watch' available:
  expected single matching bean but found 2: smartWatch,watch
*/
```

- 원인: `Bag(Hat, Watch)`의 `Watch` 자리에 들어갈 수 있는 빈이 **watch, smartWatch 2개**
  - `@Autowired`는 타입 기반이라 하나를 고르지 못함

### @Qualifier (TODO: 07)

- **이름 기반**으로 주입될 빈을 한정하는 annotation — `@Autowired`와 함께 사용

| | `@Qualifier` | `@Autowired` |
|---|---|---|
| FIELD, METHOD, PARAMETER, ANNOTATION_TYPE | O | O |
| TYPE | O | X |
| CONSTRUCTOR | **X** | O |

```java
public @interface Qualifier {
    String value() default "";
}
```

- `@Qualifier`는 생성자에는 못 붙임 → 생성자의 **파라미터**에 붙임

```java
@Component
public class Bag {
    // ...
    @Autowired
    public Bag(Hat hat, @Qualifier("watch") Watch watch) {
        this.hat = hat;
        this.watch = watch;
    }
}
```

### 스테레오타입 annotation

- `@Component`: 특별한 의미 없이 단순히 "**빈의 대상**"임을 나타냄
- **스테레오타입**: 용도에 따라 미리 여러 형태로 정형화해 놓은 타입
  - 내부적으로 `@Component`를 포함 → 빈으로 관리됨

```java
@Target({ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Component
public @interface Repository { ... }
```

| annotation | 용도 |
|---|---|
| `@Repository` | MVC에서 Model의 Repository(DAO) 계열 빈 |
| `@Service` | MVC에서 Model의 Service 계열 빈 |
| `@Controller` | MVC에서 controller로 쓰는 빈 |
| `@Configuration` | java 기반 메타 정보 클래스 |
| `@Component` | 위 스테레오타입에 해당하지 않을 때 |

- 가급적 스테레오타입을 쓰고, 해당하는 게 없으면 `@Component`

### DI 방법의 비교 — 주입 방식

| 방식 | 평가 | 특징 |
|---|---|---|
| **생성자 주입** | 가장 권장 | 모든 의존성이 반드시 필요하다는 것을 명시적으로 보여 줌, field를 blank final로 → **불변성** 확보, 순환 의존성을 빈 생성 시점에 즉시 발견 |
| setter 주입 | 선택적 의존성에 적합 | 의존성이 없어도 빈은 만들어짐 |
| field 주입 | 비추천 | 코드는 가장 간결하지만 테스트 시 Mock 주입이 어렵고 불변성 보장 안 됨 → 단위 테스트처럼 특별한 목적에만 사용 |

```java
@Component
public class A {
    private final B b;              // blank final
    public A(B b) { this.b = b; }   // 생성자 주입
}

@Component
@RequiredArgsConstructor            // lombok: final 필드를 받는 생성자 자동 생성
class B {
    private final A a;
    // public B(A a) { this.a = a; }  ← lombok이 만들어 줌
}
```

- 위 코드는 A는 B가, B는 A가 있어야 만들어짐 → **순환 참조**(닭이 먼저냐 달걀이 먼저냐)
  - 생성자 주입이면 빈 생성 시점에 **즉시** 오류로 발견
  - 다른 방식은 빈 생성 후 주입 과정에서 발견 (조금 늦음)

### DI 방법의 비교 — 설정 방식

| 비교 | 명시적 DI | 묵시적 DI |
|---|---|---|
| 관심사 분리 | 비즈니스 로직과 빈 관리 로직 분리 가능 — 주입 코드가 명확히 보임 | 비즈니스 로직과 빈 관리 로직이 결합 — 전체 빈 구조 파악이 어려움(개발 툴이 잘 지원) |
| 설정 작성 | 빈 설정 코드를 따로 관리 — 주입 코드가 복잡해질 수 있음 | 개발자가 주입 코드를 작성하지 않아도 됨 |
| 외부 라이브러리를 빈으로 | **가능** | 제한적 (라이브러리 클래스에 `@Component`를 붙일 수 없음) |

- **묵시적 DI를 기본**으로 하고, **명시적 DI를 보조**로 사용
  - 묵시적 DI가 간단하지만 명시적 DI를 안 쓸 수는 없음

## 부록: 빈의 생명 주기

### 기타 — @Bean 메서드 파라미터, @Value

- `@Bean` 메서드의 **파라미터**는 자동으로 `@Autowired`처럼 주입됨

```java
// 다른 @Bean 메서드를 직접 호출
@Bean(name = "myWasherUser")
public WasherUser washerUser() {
    WasherUser washerUser = new WasherUser();
    washerUser.setWasher(sWasher());
    return washerUser;
}

// 파라미터로 받기 - 컨테이너가 SWasher 빈을 넣어 줌
@Bean(name = "myWasherUser")
public WasherUser washerUser(SWasher washer) {
    WasherUser washerUser = new WasherUser();
    washerUser.setWasher(washer);
    return washerUser;
}
```

- **@Value**: 객체가 아닌 **스칼라 값**(문자열, 숫자 등)을 주입받을 때 사용

```java
@Target({ElementType.FIELD, ElementType.METHOD, ElementType.PARAMETER, ElementType.ANNOTATION_TYPE})
public @interface Value {
    String value();
}
```

- 주로 설정 파일에 선언된 **property를 참조**할 때 사용 → `${ }` 안에 property 이름

```java
@Value("${java.specification.version}")
int javaVersion;
```

### 빈의 생명 주기

```
생성자 호출 → Setter 호출(의존성 주입) → 초기화 메서드 → [빈 사용 가능 기간: ctx.getBean(..)] → 소멸 메서드
```

| | 초기화 메서드 | 소멸 메서드 |
|---|---|---|
| 주요 용도 | 빈에서 사용할 **자원의 초기화** | 빈에서 사용한 **자원의 정리** |
| 호출 시점 | 의존성 주입 후, 비즈니스 로직이 호출되기 전 | 모든 비즈니스 로직이 끝난 후 |
| 묵시적 빈 등록 | `@PostConstruct` | `@PreDestroy` |
| 명시적 빈 등록 | `@Bean`의 `initMethod` 속성 | `@Bean`의 `destroyMethod` 속성 |
| 주의사항 | 메서드에 **파라미터가 없어야** 함 | 메서드에 **파라미터가 없어야** 함 |

- `@PostConstruct`, `@PreDestroy`를 쓰려면 **jakarta.annotation-api** 필요

```xml
<dependency>
    <groupId>jakarta.annotation</groupId>
    <artifactId>jakarta.annotation-api</artifactId>
    <version>1.3.5</version>
</dependency>
```

- 명시적 빈 등록: 메서드 이름을 문자열로 지정

```java
@Bean(initMethod = "setup", destroyMethod = "destroy")   // SWasher에 setup(), destroy() 메서드가 있어야 함
public SWasher sWasher() {
    return new SWasher();
}
```

- 묵시적 빈 등록: 메서드에 annotation

```java
@Component
@Scope
public class Bag {
    // ...
    @PostConstruct
    public void setup() {
        System.out.println("짐싸기 전에 가방 청소");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("사용하고 나면 원위치");
    }
}
```

> 참고: jakarta.annotation-api **1.3.5**의 패키지는 아직 `javax.annotation`이고, **2.x부터** `jakarta.annotation`으로 바뀜. Spring 6에서 `import jakarta.annotation.PostConstruct;`로 쓰려면 2.x 버전을 넣어야 함.

> 참고: `@Scope`의 값을 비우면 기본값 singleton. 소멸 메서드는 컨테이너가 닫힐 때(`AnnotationConfigApplicationContext`의 `close()`) 호출됨 — `ApplicationContext` 인터페이스에는 `close()`가 없음. 교재의 `@Bean(initMethod = “setup", ...)`은 따옴표가 깨져 있어 `"setup"`으로 고침.
