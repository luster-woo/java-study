### 명시적 DI

- 빈을 생성하고 의존성을 주입하는 코드를 **별도의 파일에 명시** — "이것은 빈입니다!"

| annotation | 위치 | 역할 |
|---|---|---|
| `@Configuration` | class level | java 기반 **설정 파일**을 만들기 위한 annotation |
| `@Bean` | method level | **빈을 선언**, 메서드 이름 = 빈 이름 |

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Component                        // @Configuration 자체도 @Component를 포함
public @interface Configuration { }
```

```java
@Target({ElementType.METHOD, ElementType.ANNOTATION_TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface Bean {
    @AliasFor("name")
    String[] value() default {};   // value는 name에 대한 alias
    @AliasFor("value")
    String[] name() default {};    // 기본 빈 이름(메서드 이름)을 재정의 가능
}
```

### 메타 정보의 작성 (TODO: 02)

```java
@Configuration                      // 여기는 설정 정보가 담겨 있음
public class WasherConfig {

    @Bean                           // 메서드를 통해서 빈 생성
    public SWasher sWasher() {      // SWasher 타입의 빈, 빈 이름은 sWasher
        return new SWasher();       // 실제로 사용될 빈 객체 반환
    }

    @Bean
    public LWasher lWasher() {
        return new LWasher();
    }

    @Bean(name = "myWasherUser")    // 빈 이름을 myWasherUser로 설정
    public WasherUser washerUser() {
        // return new WasherUser(sWasher());     // 생성자로 sWasher 주입
        WasherUser washerUser = new WasherUser();
        washerUser.setWasher(sWasher());          // setter를 이용한 주입
        return washerUser;
    }
}
```

| 메서드 | 빈 타입 | 빈 이름 |
|---|---|---|
| `sWasher()` | SWasher | `sWasher` |
| `lWasher()` | LWasher | `lWasher` |
| `washerUser()` | WasherUser | `myWasherUser` (name으로 재정의) |

- 생성자 주입, setter 주입 둘 다 가능
- 의문: `washerUser()` 안에서 `sWasher()`를 호출하면 객체를 또 만드는 것 아닌가? → 아래 실행 결과에서 **같은 객체**임을 확인 (Spring은 빈을 singleton으로 관리)

### 빈 사용 (TODO: 03)

```
1. POJO로 빈 구성 → 2. 빈의 관계 정보 작성(WasherConfig, 메타 정보)
→ 3. 스프링 컨테이너가 빈 생성 및 주입 → 4. 빈 요청 → 5. 빈 반환 → 6. 빈 사용
```

```java
import org.springframework.context.ApplicationContext;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;

public class WasherUserTest {
    public static void main(String[] args) {
        // 설정 정보로 컨테이너 생성
        ApplicationContext ctx = new AnnotationConfigApplicationContext(WasherConfig.class);

        Washer sWasher = ctx.getBean(SWasher.class);        // SWasher 타입의 빈
        WasherUser user = ctx.getBean(WasherUser.class);    // WasherUser 타입의 빈
        user.useWasher("옷");

        // 같은 객체인지 확인 - Spring은 빈을 singleton으로 관리
        System.out.println(sWasher == user.getWasher());
    }
}
/* 결과
SWasher로 세탁: 옷
true
*/
```

- `user.getWasher()`를 쓰려면 WasherUser에 getter가 있어야 함

### 빈 조회

- Spring Container는 기본적으로 빈을 **타입 기반**으로 관리
- 같은 타입의 빈이 여럿이면?

```java
Washer myWasher = ctx.getBean(Washer.class);
// Exception in thread "main"
// org.springframework.beans.factory.NoUniqueBeanDefinitionException:
//   No qualifying bean of type 'com..Washer' available:
//   expected single matching bean but found 2: sWasher,lWasher
```

```
          Washer
         /      \
    SWasher    LWasher     ← Washer 타입 빈이 2개
```

- 해결: 구체 타입으로 조회하거나 **타입 + 이름**으로 조회

```java
Washer sWasher = ctx.getBean(SWasher.class);              // SWasher 타입의 빈
// 같은 타입이 여럿일 경우 타입 + 이름 기반으로 조회
Washer myWasher = ctx.getBean("sWasher", Washer.class);
System.out.println(sWasher == myWasher);
// 결과
// true
```

| 조회 방법 | 결과 |
|---|---|
| `getBean(Washer.class)` | 후보 2개 → `NoUniqueBeanDefinitionException` |
| `getBean(SWasher.class)` | SWasher 빈 하나 → 성공 |
| `getBean("sWasher", Washer.class)` | 이름으로 한정 → 성공 |

### 이제 main은 그만 (TODO: 04)

- 테스트 코드는 **test 영역**(`src/test/java`)에서 JUnit으로 작성

```xml
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter-api</artifactId>
    <version>${junit-jupiter.version}</version>
    <scope>test</scope>
</dependency>
```

```java
public class WasherTest {
    ApplicationContext ctx;

    @BeforeEach
    public void setUp() {
        ctx = new AnnotationConfigApplicationContext(WasherConfig.class);
    }

    @Test
    public void washerUserTest() {
        WasherUser user = ctx.getBean(WasherUser.class);
        user.useWasher("옷");
        Assertions.assertNotNull(user);
    }

    @Test
    public void washerTest() {
        Washer sWasher = ctx.getBean(SWasher.class);
        WasherUser user = ctx.getBean(WasherUser.class);
        Assertions.assertSame(sWasher, user.getWasher());   // singleton → 같은 객체
    }
}
```

- `@BeforeEach`로 테스트마다 컨테이너를 새로 만들고, 빈이 주입됐는지·같은 객체인지를 assertion으로 검증
