## 1. 회원 리포지토리

```java
@Repository
public class MemberRepository {

    @PersistenceContext
    private EntityManager em;

    public void save(Member member) {
        em.persist(member);
    }

    public Member findOne(Long id) {
        return em.find(Member.class, id);
    }

    public List<Member> findAll() {
        return em.createQuery("select m from Member m", Member.class)   // JPQL: 엔티티 대상
                .getResultList();
    }

    public List<Member> findByName(String name) {
        return em.createQuery("select m from Member m where m.name = :name", Member.class)
                .setParameter("name", name)
                .getResultList();
    }
}
```

| 어노테이션 | 역할 |
|---|---|
| `@Repository` | 스프링 빈 등록(컴포넌트 스캔) + **JPA 예외를 스프링 기반 예외로 변환** |
| `@PersistenceContext` | 엔티티 매니저(`EntityManager`) 주입 |
| `@PersistenceUnit` | 엔티티 매니저 팩토리(`EntityManagerFactory`) 주입 |

- `persist` 시점에 영속성 컨텍스트에 올라가며 PK(`@GeneratedValue`)가 채워짐 → 저장 직후 `member.getId()` 사용 가능 (INSERT는 커밋 때)

## 2. 회원 서비스

```java
@Service
@Transactional(readOnly = true)          // 클래스 기본: 읽기 전용
@RequiredArgsConstructor                 // final 필드 생성자 자동 생성
public class MemberService {

    private final MemberRepository memberRepository;

    /** 회원가입 */
    @Transactional                       // 쓰기: readOnly = false로 덮어씀
    public Long join(Member member) {
        validateDuplicateMember(member); // 중복 회원 검증
        memberRepository.save(member);
        return member.getId();
    }

    private void validateDuplicateMember(Member member) {
        List<Member> findMembers = memberRepository.findByName(member.getName());
        if (!findMembers.isEmpty()) {
            throw new IllegalStateException("이미 존재하는 회원입니다.");
        }
    }

    /** 전체 회원 조회 */
    public List<Member> findMembers() { return memberRepository.findAll(); }

    public Member findOne(Long memberId) { return memberRepository.findOne(memberId); }
}
```

### @Transactional

- JPA의 모든 데이터 변경은 트랜잭션 안에서 + **트랜잭션 = 영속성 컨텍스트 범위**
- **`readOnly = true`**: 데이터 변경이 없는 읽기 전용 메서드에 사용
  - 영속성 컨텍스트를 **플러시하지 않음** (변경 감지 스냅샷 비교 생략) → 약간의 성능 향상
  - DB 드라이버가 지원하면 DB에서도 성능 향상
- 패턴: **조회가 많으면 클래스에 `readOnly = true`, 쓰기 메서드에만 `@Transactional`**
- `org.springframework.transaction.annotation.Transactional` 사용 (옵션이 더 많음)

> 참고: 이름으로 중복 검증해도 **동시에 같은 이름으로 가입하면 둘 다 통과**할 수 있다(멀티 쓰레드). 실무에선 회원명 컬럼에 **유니크 제약 조건**을 추가하는 게 안전하다.

### 의존성 주입 — 생성자 주입을 쓰자

| 방식 | 문제 |
|---|---|
| 필드 주입 `@Autowired MemberRepository repo;` | 테스트에서 바꿔 끼우기 어려움 |
| Setter 주입 | 런타임에 누가 바꿀 수 있음 (애플리케이션 로딩 후 바꿀 일이 없음) |
| **생성자 주입** ✅ | 변경 불가능한 안전한 객체, 테스트 시 의존성 누락을 **컴파일 시점**에 알 수 있음 |

```java
public class MemberService {
    private final MemberRepository memberRepository;     // final: 세팅 누락을 컴파일러가 체크

    public MemberService(MemberRepository memberRepository) {  // 생성자가 하나면 @Autowired 생략 가능
        this.memberRepository = memberRepository;
    }
}
```

- **롬복 `@RequiredArgsConstructor`** = final 필드만으로 생성자를 만들어줌 → 위 코드를 한 줄로

> 참고: 스프링 부트(스프링 데이터 JPA)를 쓰면 `EntityManager`도 `@PersistenceContext` 대신 **생성자 주입** 가능 → 소스의 `ItemRepository`, `OrderRepository`는 `@RequiredArgsConstructor` + `private final EntityManager em;`

## 3. 회원 기능 테스트

테스트 요구사항: 회원가입 성공 / 같은 이름이 있으면 예외

```java
@SpringBootTest
@Transactional
public class MemberServiceTest {

    @Autowired MemberService memberService;
    @Autowired MemberRepository memberRepository;

    @Test
    public void 회원가입() throws Exception {
        //Given
        Member member = new Member();
        member.setName("kim");
        //When
        Long saveId = memberService.join(member);
        //Then
        assertEquals(member, memberRepository.findOne(saveId));   // 같은 영속성 컨텍스트 → 같은 인스턴스
    }

    @Test
    public void 중복_회원_예외() throws Exception {
        //Given
        Member member1 = new Member();
        member1.setName("kim");
        Member member2 = new Member();
        member2.setName("kim");
        //When
        memberService.join(member1);
        //Then
        assertThrows(IllegalStateException.class, () -> memberService.join(member2));
    }
}
```

| 어노테이션 | 역할 |
|---|---|
| `@SpringBootTest` | 스프링 부트를 띄우고 테스트 (없으면 `@Autowired` 다 실패) |
| `@Transactional` | 테스트마다 트랜잭션 시작, 끝나면 **강제 롤백** (테스트에 붙었을 때만) → 반복 가능한 테스트 |
| ~~`@RunWith(SpringRunner.class)`~~ | JUnit4용, 최신 버전에선 불필요 |

- 회원가입 테스트에서 INSERT 로그가 안 보이는 이유: 롤백되니 **flush를 안 함**. 보고 싶으면 `@Rollback(false)` 또는 `em.flush()`
- **Given, When, Then** 패턴 권장 (필수는 아니지만 기본으로 응용)

### 테스트 케이스를 위한 설정 — 메모리 DB

- 테스트는 **격리된 환경**에서 실행하고 끝나면 초기화 → **메모리 DB**가 이상적
- 테스트용 설정 파일 분리: `src/test/resources/application.yml` (있으면 이게 우선, 없으면 main 것을 읽음)

```yaml
spring:
#  datasource:
#    url: jdbc:h2:mem:testdb     # 메모리 모드
#  jpa: ...
logging.level:
  org.hibernate.SQL: debug
```

- **스프링 부트는 datasource 설정이 없으면 기본으로 메모리 DB 사용**, 드라이버도 등록된 라이브러리로 찾아줌, `ddl-auto`도 **`create-drop`** → 별도 설정이 거의 필요 없다

> 참고: 강의 소스(`jpashop-v20250325`)에는 `test/resources/application.yml`이 **없다** → 테스트도 main의 `jdbc:h2:tcp://localhost/~/jpashop`으로 붙으므로 **H2 서버를 켜 둬야** 테스트가 돈다. 서버 없이 돌리려면 위 파일을 추가.
