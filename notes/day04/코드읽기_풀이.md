## 출력 예측

### 출력 1 · 인터페이스 default 메서드

```java
interface Greet {
    default String hi() { return "Hi"; }
}
class Kor implements Greet {
    public String hi() { return "안녕"; }
}
class Eng implements Greet { }

Greet[] gs = { new Kor(), new Eng() };
for (Greet g : gs) System.out.print(g.hi() + " ");
```

**답**

```
안녕 Hi 
```

- `default` 메서드 = 인터페이스 안에 **몸통이 있는** 메서드 (Java 8~)
- 구현 클래스가 재정의하면 → 재정의한 것 (Kor : 안녕)
- 재정의 안 하면 → 인터페이스의 기본 구현 그대로 (Eng : Hi)
- 일반 클래스 상속에서 "재정의 안 하면 부모 것 사용"과 같은 원리
- 쓰는 이유 : 인터페이스에 메서드를 새로 추가해도, 이미 구현한 클래스들이 전부 깨지지 않게

### 출력 2 · enum 메서드

```java
enum Size { S, M, L }

Size s = Size.valueOf("M");
System.out.println(s.ordinal() + " " + s.compareTo(Size.L) + " " + Size.values().length);
```

**답**

```
1 -1 3
```

| 식 | 값 | 이유 |
|---|---|---|
| `s.ordinal()` | 1 | 순서는 0부터 (S=0, M=1, L=2) |
| `s.compareTo(Size.L)` | -1 | ordinal 차이 = 1 - 2 |
| `Size.values().length` | 3 | 상수 3개 |

### 출력 3 · 한정된 제네릭 메서드

```java
static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

System.out.println(max(3, 7));
System.out.println(max("apple", "banana"));
System.out.println(max("b", "B"));
```

**답**

```
7
banana
b
```

- `<T extends Comparable<T>>` : T는 "비교할 수 있는(compareTo가 있는)" 타입만 → 그래서 `a.compareTo(b)` 사용 가능
- Integer, String 둘 다 Comparable을 구현 → **같은 메서드 하나**로 숫자도 문자열도 비교
- 문자열은 사전순(유니코드 값) : `'b'`(98) > `'B'`(66) → 소문자가 더 크다

## 버그 찾기

### 버그 1 · 컴파일 에러

```java
interface Shape {
    double area();
}
class Square implements Shape {
    double side = 2;
    double area() { return side * side; }
}
```

**문제점**

- 인터페이스 메서드는 자동으로 `public abstract`
- Square에서 접근 제한자를 안 붙이면 default(package) → public보다 **좁아짐**
- 오버라이딩 조건 "접근 제한자는 같거나 넓게" 위반 → `attempting to assign weaker access privileges`

**수정:** `public double area()`

→ 인터페이스를 구현할 땐 **항상 public**

### 버그 2 · 실행 중 에러

```java
List list = new ArrayList();
list.add("a");
list.add(1);
String s = (String) list.get(1);
```

**문제점**

- `<>` 없이 쓴 raw type → 사실상 Object 리스트 → 숫자도 들어감
- 꺼내서 String으로 형변환하는 순간 `ClassCastException`

**수정:** `List<String> list = new ArrayList<>();`

→ `list.add(1)`에서 **컴파일 에러**로 막아줌. 에러를 실행 전에 잡는 것 = 제네릭을 쓰는 이유

## 빈칸 채우기

### 빈칸 1 · 제네릭 스택

```java
void push(T x) {
    if (size == data.length) data = Arrays.copyOf(data, data.length * 2);
    data[size++] = x;
}

T pop() {
    return data[--size];
}
```

| 빈칸 | 답 | 이유 |
|---|---|---|
| ① | `data.length * 2` | 꽉 차면 2배 크기로 복사 |
| ② | `size++` | 현재 칸(size)에 **넣고 나서** 증가 (후위) |
| ③ | `--size` | 맨 위는 `size - 1` 칸 → **먼저 줄이고** 꺼내기 (전위) |

```
push 3번 후 : [a][b][c][ ]   size = 3
pop        : size를 2로 줄이고 data[2] = c 반환
```

- `new T[2]`는 안 됨 → `(T[]) new Object[2]`로 우회 (제네릭 주의사항 : 제네릭 배열 생성 불가)
- 실무라면 pop 전에 비었는지 확인 + 꺼낸 칸을 null로 (D4P2 풀이에 반영함)

### 빈칸 2 · 점수 → 등급

```java
enum Grade {
    A(90), B(80), C(0);

    private final int min;

    Grade(int min) { this.min = min; }

    static Grade of(int score) {
        for (Grade g : values()) {
            if (score >= g.min) return g;
        }
        return C;
    }
}
// Grade.of(85) → B
```

- `this.min = min;` : 파라미터와 필드 이름이 같으니 this 필수
- `values()` : 선언 순서(A, B, C)대로 배열 반환
- 85점 → A(90) 실패 → B(80) 성공 → B
- **높은 등급부터 선언**해 둔 덕분에 "처음 만족하는 것"이 답이 된다. 순서를 C, B, A로 바꾸면 전부 C가 나오는 버그

## 핵심 정리

| 함정 | 기억할 것 |
|---|---|
| default 메서드 | 재정의 안 하면 인터페이스의 기본 구현 사용 |
| `ordinal()` | 0부터 시작 |
| enum `compareTo` | ordinal 차이 |
| `<T extends Comparable<T>>` | compareTo가 있는 타입만 → 숫자·문자열 공용 비교 |
| 문자열 비교 | 유니코드 순 → 소문자 > 대문자 |
| 인터페이스 구현 | 반드시 `public` |
| raw type | 컴파일러가 못 막음 → `ClassCastException`. 항상 `<타입>` |
| 제네릭 배열 | `new T[]` 불가 → `(T[]) new Object[]` |
| push / pop | `data[size++]` / `data[--size]` |
| enum `values()` | 선언 순서 그대로 → 순서가 로직에 영향 |
