## 관점 지향 프로그래밍

### AOP 등장 배경 — 기존 방식의 문제점

- 기존 객체지향 방식: 부가 기능을 **개발자가 직접 호출**하고 결과까지 관리 → 핵심 비즈니스 로직에 집중하기 어려움 (**OOP 방식의 한계**)
- **코드 중복(copy & paste) 심화**: 비슷한 기능의 메서드마다 같은 부가 로직을 반복 작성
- 교재 예시(그림): 휴양지로 놀러 간 호텔에서 청소를 부탁해야 하는 경우

### AOP (Aspect Oriented Programming)

- 메서드에도 **핵심 관심**(비즈니스 로직)과 **횡단 관심**(부가 로직)이 섞여 있음

| 구분 | 의미 | 예 |
|---|---|---|
| **핵심 관심사** (Core Concerns) | 객체가 제공하는 고유의 기능 | 회원 등록 (아래 예제의 `repo.insert`) |
| **횡단 관심사** (Cross-cutting Concerns) | 핵심 기능을 보조하는 기능 | 시간 측정, 로그 추적, 트랜잭션 관리 |

```
               Service A      Service B       Service C        ← 핵심 관심사 (세로)
로깅        ────────●─────────────●──────────────●──────────
트랜잭션    ────────●─────────────●──────────────●──────────   ← 횡단 관심사 (가로로 관통)
성능 측정   ────────●─────────────●──────────────●──────────
```

- AOP: 기능을 비즈니스 로직이 아니라 **개별 관점(Aspect)**으로 바라보는 기법

| 키워드 | 의미 |
|---|---|
| **모듈화** (Modularize) | 횡단 관심사를 따로 빼서 정리 |
| **재사용** (Reuse) | 한 번 만들어 두고 필요한 곳에 "팻말"만 검 |
| **전념** (Focus) | 개발자는 비즈니스 로직에만 집중 |

- **AOP는 OOP를 대체하지 않음 → 보조**하는 목적

### AOP 코드로 미리 살펴보기

- 기존 메서드: 핵심 로직 한 줄을 로깅·성능 측정·트랜잭션 코드가 둘러쌈

```java
public void insert(Member member) {
    System.out.println("[LOG] insert 시작: " + member);   // 로깅
    long start = System.currentTimeMillis();              // 성능 측정 시작
    Connection con = null;
    try {
        con = dbUtil.getConnection();                     // 트랜잭션 - DB 접속
        con.setAutoCommit(false);                         // 트랜잭션 - 시작
        repo.insert(con, member);                         // ★ 핵심 로직: 멤버 등록
        con.commit();                                     // 트랜잭션 - 커밋
    } catch (Exception e) {
        if (con != null) con.rollback();                  // 트랜잭션 - 롤백
        throw new RuntimeException(e);
    } finally {
        dbUtil.close(con);
    }
    long end = System.currentTimeMillis();                // 성능 측정 종료
    System.out.println("[LOG] insert 완료: " + (end - start) + "ms");  // 로깅
}
```

- AOP 적용 후: 서비스엔 핵심 로직만, 부가 기능은 **Aspect** 클래스로 분리

```java
public void insert(Member member) {
    repo.insert(member);   // 핵심 로직 끝!
}
```

```java
@Aspect
public class ServiceAspect {
    // 1. 트랜잭션 관점
    @Around("execution(* insert(..))")
    public Object handleTx(ProceedingJoinPoint pjp) throws Throwable { ... }

    // 2. 로깅 관점
    @Around("execution(* insert(..))")
    public Object doLogging(ProceedingJoinPoint pjp) throws Throwable { ... }

    // 3. 성능 측정 관점
    @Around("execution(* insert(..))")
    public Object measurePerformance(ProceedingJoinPoint pjp) throws Throwable { ... }
}
```

### AOP 용어

| 용어 | 내용 |
|---|---|
| **Target** | 핵심 기능(비즈니스 로직)을 담은 Bean 객체 → 부가 기능을 부여할 **대상** |
| **Aspect** | 여러 클래스에 공통으로 적용되는 횡단 관심 사항 (AOP의 기본 모듈, 1개 이상의 Advice 집합) = **Advice**(무엇을) + **Pointcut**(어디에) |
| **Advice** | 횡단 관심 코드, 특정 Join Point에서 동작할 메서드. 동작 시점에 따라 `@Around`, `@Before`, `@After` 등의 타입 |
| **Join Point** | Advice를 적용할 수 있는 모든 지점 (메서드 실행, 생성자 호출 등). **Spring AOP는 메서드 실행 지점으로 제한** |
| **Pointcut** | Join Point 중 Advice를 적용할 곳을 고르는 조건(표현식). Aspect는 Pointcut에 일치하는 모든 Join Point에서 실행 |
| **Weaving** | Pointcut으로 고른 Target의 Join Point에 Advice를 적용하는 것. 컴파일·클래스 로딩·런타임 시점 가능, **Spring AOP는 런타임** |

```
            Aspect = Advice(무엇을, 언제) + Pointcut(어디에)
                          │ Weaving (런타임)
                          ▼
Target ─ Join Point ─ Join Point ─ Join Point ...
              ▲ Pointcut에 일치하는 지점에만 Advice 실행
```

### AOP 적용 과정 예시

- 요구: **setXXX 메서드가 호출되면**(어디에) **핵심 로직 실행 전에**(시점) **로그를 남겨라**(횡단 관심사)

```java
private String name;

public void setName(String name) {
    this.name = name;   // 핵심 로직
}
```

| 항목 | 내용 |
|---|---|
| pointcut (어디서) | `setXXX` 형태의 메서드 |
| advice type (언제) | `@Before` |
| advice code (무엇을) | `log.debug("설정 중")` |
