## 예외 처리

### 기존의 error page 연결 — web.xml

- 서블릿 시절에는 `web.xml`에서 에러 코드별 페이지를 전역으로 지정

```xml
<error-page>
    <error-code>404</error-code>
    <location>/error/404.jsp</location>
</error-page>
<error-page>
    <error-code>500</error-code>
    <location>/error/500.jsp</location>
</error-page>
```

- 그런데 Spring Boot 프로젝트에는 `web.xml`이 없음
- 없는 경로(예: `http://localhost:8080/member/login`)를 요청하면 어떻게 될까?

### Spring Boot의 error page 연결 — BasicErrorController

- Spring Boot는 **`BasicErrorController`**가 에러 페이지 연결을 담당

```text
에러 발생
  │
  ├─ 에러 코드에 맞는 페이지가 있나? (예: /error/404.jsp)
  │     └─ Yes → 그 페이지 사용
  │
  └─ No → /error.jsp 가 있나?
          ├─ Yes → /error.jsp 사용 (405, 500 등 공통)
          └─ No  → Whitelabel Error Page 사용
```

- 한계
  - 페이지만 보여 줄 뿐 **예외를 로깅할 수 없음**
  - 예외 상황에서 **공통으로 처리할 일**이 있다면? → `@ControllerAdvice`
- Whitelabel error page 관련 설정 — 대부분 default 권장

```properties
# 에러 페이지 경로, default: /error
server.error.path=/error-handler
# 에러 메시지 포함 여부, default: never
server.error.include-message=always
# 예외 정보 포함 여부, default: false
server.error.include-exception=true
# 바인딩 오류 포함 여부, default: never
server.error.include-binding-errors=always
```

### @ControllerAdvice

- 특정 대상 Controller들에게 "조언"하는 컴포넌트 — `@Component`가 붙어 있어 빈으로 등록됨
- 대상 지정: `basePackages`(= `value`) 또는 `annotations`

```java
@Target(ElementType.TYPE)
@Component
public @interface ControllerAdvice {
    @AliasFor("basePackages")
    String[] value() default {};
    @AliasFor("value")
    String[] basePackages() default {};
    Class<? extends Annotation>[] annotations() default {};
}
```

- 전역 예외 처리는 **`@ExceptionHandler`** 메서드로 — 처리할 예외 타입을 지정

```java
@Target(ElementType.METHOD)
public @interface ExceptionHandler {
    @AliasFor("exception")
    Class<? extends Throwable>[] value() default {};
    @AliasFor("value")
    Class<? extends Throwable>[] exception() default {};
}
```

```java
@ControllerAdvice(annotations = Controller.class)   // @Controller 클래스들이 대상
@Slf4j
public class MvcExceptionHandler {

    @ExceptionHandler(Exception.class)
    public ModelAndView handleMvcException(Exception e) {
        log.error("[@Controller에서 발생한 오류] ", e);   // 이제 로깅 가능
        ModelAndView mav = new ModelAndView();
        mav.addObject("exception", e.getMessage());
        mav.setViewName("error/custom");
        return mav;
    }
}
```

### @ControllerAdvice의 동작

| 요청 | 결과 | 누가 처리하나 |
|---|---|---|
| 1. `GET /simple/problem` | 500 — Controller 안에서 예외 발생 | **@ControllerAdvice** (1순위) |
| 2. `GET /simple/notexist` | 404 — 매핑된 핸들러 없음 | **BasicErrorController** (2순위) |
| 3. `GET /simple/regist` | 405 — `/regist`는 POST만 매핑 | **BasicErrorController** (2순위) |

```text
DispatcherServlet ─► HandlerMapping ─► HandlerAdapter ─► @Controller
                                                          GET  /simple/problem → 예외(500)
                                                          POST /simple/regist
     1 (Controller에서 난 예외)  ─► @ControllerAdvice(annotations = Controller.class)   ← 1순위
     2, 3 (Controller까지 못 감) ─► BasicErrorController                              ← 2순위
```

- 정리: **비즈니스 로직 오류는 `@ControllerAdvice`가 직접 처리, 나머지는 `BasicErrorController`에 위임**

### BasicErrorController 활용

- 경로: `server.error.path` → 없으면 `error.path` → 없으면 `/error`
- **HTML 요청과 AJAX 요청을 나눠서 처리**
  - `produces = text/html` → `errorHtml()` → 에러 **페이지**(ModelAndView)
  - 그 밖의 요청 → `error()` → **JSON**(`ResponseEntity<Map>`)

```java
@Controller
@RequestMapping("${server.error.path:${error.path:/error}}")
public class BasicErrorController extends AbstractErrorController {

    public BasicErrorController(ErrorAttributes errorAttributes, ErrorProperties errorProperties) {
        this(errorAttributes, errorProperties, Collections.emptyList());
    }

    @RequestMapping(produces = MediaType.TEXT_HTML_VALUE)   // 브라우저(HTML) 요청
    public ModelAndView errorHtml(HttpServletRequest request, HttpServletResponse response) {
        HttpStatus status = getStatus(request);
        Map<String, Object> model = Collections.unmodifiableMap(
                getErrorAttributes(request, getErrorAttributeOptions(request, MediaType.TEXT_HTML)));
        response.setStatus(status.value());
        ModelAndView modelAndView = resolveErrorView(request, response, status, model);
        return (modelAndView != null) ? modelAndView : new ModelAndView("error", model);
    }

    @RequestMapping                                           // 그 밖의 요청(AJAX 등)
    public ResponseEntity<Map<String, Object>> error(HttpServletRequest request) {
        // ...
        return new ResponseEntity<>(body, status);
    }
}
```

- 에러 페이지에 담기는 정보(`ErrorAttributes`)를 바꾸고 싶으면 → `ErrorAttributes`를 재정의(실습 과제)

## 참고

> 참고: 교재는 `server.error.include-exception`의 default를 `never`로 적었지만, 이 속성은 boolean이라 default는 `false`(나머지 `include-message`·`include-binding-errors`는 `never`가 맞음).

- `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody` → REST API에서 예외를 JSON으로 응답할 때 사용
- `@ExceptionHandler`를 Controller 클래스 안에 두면 그 Controller에서 난 예외만 처리. `@ControllerAdvice`에 두면 대상 Controller 전체에 적용
- `server.error.include-*` 를 `always`로 두면 내부 정보가 응답에 노출될 수 있어 운영 환경에서는 default(never/false) 유지가 안전
