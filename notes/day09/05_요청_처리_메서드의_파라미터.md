## 요청 처리 메서드의 파라미터

### 파라미터로 쓸 수 있는 것들

- 필요한 타입을 파라미터에 **순서 상관없이** 선언하면 Spring이 **자동 주입**

| 분류 | 예 |
|---|---|
| Servlet 관련 객체 | `HttpServletRequest`, `HttpServletResponse`, `HttpSession`, `Locale`, ... |
| Spring MVC 객체 | `Model`, `RedirectAttributes`, `SessionStatus`, ... |
| 애너테이션 파라미터 | `@RequestParam`, `@ModelAttribute`, `@CookieValue`, ... |

- Servlet 관련 객체 활용 예 — 로그아웃

```java
@GetMapping("/logout")
@ResponseBody
public Map<String, Object> logout(Model model, HttpServletRequest req, HttpSession session) {
    Map<String, Object> result = Map.of("loginUser", session.getAttribute("loginUser"));
    session.invalidate();
    return result;
}
```

### @RequestParam

- `HttpServletRequest`의 parameter 조회에 사용
- 요청 파라미터 name과 **같은 이름의 변수**에 매핑
  - `name` 속성으로 파라미터 이름 지정
  - name과 변수명이 같으면 생략 가능
- 타입은 primitive 또는 wrapper / 여러 값이면 배열 또는 `List`/`Set`

```java
@Target(ElementType.PARAMETER)
public @interface RequestParam {
    @AliasFor("value")
    String name() default "";                               // 요청 파라미터 이름
    boolean required() default true;                        // 필수 여부
    String defaultValue() default ValueConstants.DEFAULT_NONE;
}
```

```java
@GetMapping("/add")
public @ResponseBody Map<String, Object> add(@RequestParam Integer num1,
                                             @RequestParam("num2") Integer secondNum) {
    return Map.of("result", num1 + secondNum);
}
// 화면에서 넘어와야 하는 파라미터 이름: num1, num2
// GET /add?num1=3&num2=4 → {"result":7}
```

### @ModelAttribute

- 입력 항목이 100개짜리 객체라면? `@RequestParam`을 100개 쓸 수는 없음
- **파라미터들을 DTO의 property 이름 기준으로 setter와 자동 연결**해서 DTO 생성
  - `"email"` 파라미터 → `setEmail("...")`
- **record**는 setter가 없으므로 생성자로 바로 객체 생성

```java
@PostMapping("/regist")
public @ResponseBody Map<String, Object> regist(@ModelAttribute Member member, Model model) {
    log.debug("member: {}", member);
    log.debug("model: {}", model.getAttribute("member"));   // 자동으로 model에도 들어가 있음
    return Map.of("result", member);
}
```

- 내부적으로 일어나는 일

| 순서 | 동작 |
|---|---|
| 1 | **기본 생성자**로 객체 생성 — 없다면 **유일한 생성자** 사용(그 생성자의 파라미터가 모두 필요) |
| 2 | **setter**로 property 설정 |
| 3 | **model에 attribute 추가** — 이름은 클래스 이름의 camel case(`Member` → `member`) |

### @CookieValue

- 쿠키의 **name에 매핑된 value**를 꺼낼 때 편리
  - 쿠키 생성은 기존과 동일(`Cookie` 객체 + `response.addCookie`)
  - `@RequestParam`처럼 **자동 형 변환** 지원

```java
@GetMapping("/cookie")
public @ResponseBody Map<String, Object> cookie(@CookieValue String name,
                                                @CookieValue int age,
                                                HttpServletRequest req) {
    // 기존 방식: 쿠키 배열을 돌면서 이름으로 찾기
    Cookie[] cookies = req.getCookies();
    if (cookies != null) {
        Arrays.stream(cookies)
              .filter(c -> c.getName().equals("name") || c.getName().equals("age"))
              .forEach(c -> System.out.println(c.getValue()));
    }
    return Map.of("name", name, "age", age);   // @CookieValue는 한 줄로 끝
}
```

### Redirection과 Flash Scope

- redirect 때 데이터를 넘기는 방법들

| 방법 | 문제 |
|---|---|
| URL 뒤에 query string | URL이 지저분해짐 |
| session에 저장 | 한 번 쓰고 말 데이터인데 사용 후 직접 지워야 함 |
| **`RedirectAttributes`** (`Model`을 상속) | 아래 두 메서드 사용 |

| 메서드 | 동작 |
|---|---|
| `addAttribute(key, value)` | query-string으로 다음 페이지에 전달 → **문자열 형태만** 가능 |
| `addFlashAttribute(key, value)` | **Flash Scope** — redirect가 끝날 때까지만 저장되는 Spring 지원 scope |

- Flash Scope 특징
  - 범위: **request < flash < session**
  - session에 객체 타입 그대로 저장 → redirect 과정에서 request로 옮기고 session에서는 삭제
  - flash scope에 담아도 전달이 안 되는 경우엔 **데이터 유실**
    - `addViewControllers`로 처리하는 경로(`@Controller`가 관리하지 않음)
    - 다른 context의 리소스로 redirect하는 경우

```java
@GetMapping("/redir-attr")
public String redirAttribute(RedirectAttributes redirs, HttpSession session, Model model) {
    session.setAttribute("bySession", "annoying");
    model.addAttribute("byModel", "boring");
    redirs.addAttribute("byParam", "dirty");
    redirs.addFlashAttribute("byFlash", "SSG");
    return "redirect:/";
}
```

```jsp
<a href="${root}/simple/redir-attr">정보 확인</a>
<ul>
    <li>bySession: ${sessionScope.bySession}</li>
    <li>byModel:   ${requestScope.byModel}</li>
    <li>byFlash:   ${requestScope.byFlash}</li>
    <li>byParam:   ${param.byParam}</li>
</ul>
```

| 항목 | 초기 | redirect 후 | 새로고침 |
|---|---|---|---|
| bySession | - | annoying | annoying (세션에 남아 있음) |
| byModel | - | - (redirect로 request가 새로 생겨 사라짐) | - |
| byFlash | - | SSG | - (한 번 쓰고 사라짐) |
| byParam | - | dirty (URL에 `?byParam=dirty`) | dirty (URL에 남아 있음) |

## 참고

- redirect 후 `byModel`이 보이지 않는 것은 교재의 "초기 / redirect 후 / 새로고침" 실습에서 확인하는 포인트. 위 표는 각 scope의 동작 규칙대로 정리한 예상 결과
- `@ModelAttribute`는 생략해도 됨 — 단순 타입이 아닌 파라미터는 기본으로 `@ModelAttribute`로 처리
