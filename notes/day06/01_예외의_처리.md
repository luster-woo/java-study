# 예외의 처리

> 교재: 15기_자바_live_09_exception_0126_오후 (전공)

> [day06 목록](../README.md) · [try_catch_finally →](02_try_catch_finally.md)

### 에러와 예외

- 어떤 원인으로 애플리케이션이 오동작하거나 비정상 종료되는 경우
- 심각도에 따라 **Error** 와 **Exception** 으로 나눔

| 구분 | Error | Exception |
| --- | --- | --- |
| 상황 | 애플리케이션을 잘못 작성한 경우 | 잘못 작성한 경우 + 작성 의도와 다르게 사용되는 경우 |
| 예 | 메모리 부족, Stack Overflow | null 객체 사용, 읽으려는 파일이 없음 |
| 대처 | 디버깅으로 코드 개선 | 디버깅으로 코드 개선 + **예외 처리 코드로 상황 수습** |

- **exception handling(예외 처리)**: 예외가 발생해도 비정상 종료를 막고 정상 실행 상태를 유지하는 것
- 예외를 감지하고, 예외 발생 시 동작할 코드를 미리 작성해야 함

### 예외 클래스의 계층

```
Object
 └─ Throwable
     ├─ Error ─────────────── OutOfMemoryError ...            (Error 계열)
     └─ Exception
         ├─ IOException ───── FileNotFoundException            ┐
         ├─ SQLException                                       ├ Checked exception 계열
         ├─ ...                                                ┘
         └─ RuntimeException ─ ArithmeticException ...         (Unchecked exception 계열)
```

| 구분 | 대상 | 컴파일러 검사 |
| --- | --- | --- |
| **checked exception** | Exception 하위 중 RuntimeException 계열 제외 | 대처 코드가 없으면 **컴파일 안 됨** |
| **unchecked exception** | RuntimeException 하위 | 대처 코드가 없어도 컴파일 진행 |

- 누가 검사하나: **컴파일러**가 / 무엇을: **예외 대처 코드가 있는지**를

### 예외의 발생

- 배열 범위를 벗어나면 그 자리에서 프로그램이 갑자기 종료됨
- 컴파일은 문제없었으므로 RuntimeException 계열

```java
public class SimpleException {
    public static void main(String[] args) {
        int[] intArray = { 10 };
        System.out.println(intArray[2]);
        System.out.println("프로그램 종료합니다.");   // 실행되지 않음
    }
}
/* 출력
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 2 out of bounds for length 1
	at SimpleException.main(SimpleException.java:4)
*/
```

> 참고: 교재 출력은 `ArrayIndexOutOfBoundsException: 2`(옛 JDK 형식). JDK 11 이상에서는 `Index 2 out of bounds for length 1` 로 나옴.

## try ~ catch 구문

```java
try {
    // 예외가 발생할 수 있는 코드
} catch (XXException e) {   // 던져진 예외를 받음
    // 예외가 발생했을 때 처리할 코드
}
```

- 예외 발생 시 JVM이 `new XXException()` 객체를 만들어 던짐(throw) → 맞는 catch가 받음
- 예외가 처리되면 프로그램이 정상 종료됨

### Exception 객체의 정보 활용 — Throwable 주요 메서드

| 메서드 | 설명 |
| --- | --- |
| `String getMessage()` | 예외에 대한 구체적인 메시지 반환 |
| `Throwable getCause()` | 예외의 원인이 된 Throwable 객체 또는 null 반환 |
| `void printStackTrace()` | 예외가 발생한 메서드까지의 호출 스택 출력. 주로 디버깅용 |

- catch에서 아무것도 기록하지 않으면 무슨 일이 있었는지 알 수 없음

```java
public class SimpleTryCatch {
    public static void main(String[] args) {
        int[] intArray = { 10 };
        try {
            System.out.println(intArray[2]);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.printf("예외 처리: 배열 크기 확인 필요: %s%n", e.getMessage());
            e.printStackTrace();
        }
        System.out.println("프로그램 종료합니다.");
    }
}
/* 출력
예외 처리: 배열 크기 확인 필요: Index 2 out of bounds for length 1
java.lang.ArrayIndexOutOfBoundsException: Index 2 out of bounds for length 1
	at SimpleTryCatch.main(SimpleTryCatch.java:5)
프로그램 종료합니다.
*/
```

### try-catch 문에서의 흐름

- try 블록에서 예외 발생 시
    - JVM이 해당 예외 객체를 생성해 던짐(`throw new XXException()`)
    - 그 예외를 처리할 수 있는 catch 블록이 받아서 처리
    - 맞는 catch 블록을 못 만나면 예외 처리 실패
    - 정상 처리되면 try-catch 블록을 벗어나 다음 문장 진행
- try 블록에서 예외가 없으면 catch를 거치지 않고 try-catch 다음 문장 실행

```
예외 없음:  try 전체 실행 ──────────────────→ 다음 문장
예외 발생:  try 중간에서 중단 → catch 실행 ──→ 다음 문장
```

```java
public class TryCatchFlow {
    static void run(int num) {
        try {
            System.out.println("code 1, num: " + num);
            int i = 1 / num;
            System.out.println("code 2 - 예외 없음");
        } catch (ArithmeticException e) {
            System.out.println("code 3 - 예외 처리 완료");
        }
        System.out.println("code 4");
    }
    public static void main(String[] args) {
        run(0);   // code 1, num: 0 → code 3 → code 4
        run(1);   // code 1, num: 1 → code 2 → code 4
    }
}
```

> 교재는 `new Random().nextInt(2)` 로 num을 0 또는 1로 뽑고 "각각 무엇이 출력되나?"를 묻는다. 위 코드는 두 경우를 차례로 실행한 것.

### Checked Exception 처리

- 처리하지 않으면 컴파일 불가
- 중요한 것은 예외가 실제로 나느냐가 아니라 **"예외 발생 시 어떻게 할 것인가"**

```java
Class<?> myClass = Class.forName("java.lang.String");
// error: unreported exception ClassNotFoundException; must be caught or declared to be thrown
```

```java
try {
    Class<?> myClass = Class.forName("java.lang.String");
    System.out.println("로딩된 클래스: " + myClass.getSimpleName());   // 로딩된 클래스: String
} catch (ClassNotFoundException e) {
    System.out.println("클래스를 찾을 수 없음: " + e.getMessage());
}
System.out.println("프로그램 정상 종료");                                 // 프로그램 정상 종료
```

### 다중 exception handling

- try 블록에서 여러 종류의 예외가 나면 catch 블록을 여러 개 붙일 수 있음
- 예외 종류별로 catch 블록 구성
- 처리할 catch를 찾을 때 **다형성**이 적용됨 (자식 예외는 조상 타입 catch에 잡힘)

```java
try {
    // 예외가 발생할 만한 코드
} catch (XXException e) {
    // XXException 처리
} catch (YYException e) {
    // YYException 처리
} catch (Exception e) {
    // 그 밖의 Exception 처리
}
```

- **작성 순서 주의**
    - 상위 타입 catch가 먼저 오면 뒤의 catch는 실행될 기회가 없음 → 컴파일 오류
    - 상속 관계에서는 **작은 범위(자식) → 큰 범위(조상)** 순으로
    - 상속 관계가 없으면 순서 무관

```java
try {
    new FileInputStream("none.txt");
} catch (Exception e) {
} catch (FileNotFoundException e) {   // error: exception FileNotFoundException has already been caught
}
```

> 참고: 교재의 `Unreachable catch block ...` 은 Eclipse 메시지. javac(명령행)에서는 `has already been caught` 로 나옴.

### 다중 예외 처리를 이용한 Checked Exception 처리

- 예외 처리는 가능한 **구체적으로**
- 하나의 `catch (Exception e)` 로 다 받으면 상황별 처리가 어려움 → 가급적 상황별로 처리 권장
- 심각하지 않은 예외까지 세분화하는 것도 낭비 → `|` 로 **상속 관계가 없는** 여러 예외를 한 catch에서 처리

```java
import java.io.FileInputStream;
import java.io.FileNotFoundException;
import java.sql.DriverManager;
import java.sql.SQLException;

public class MultiCatch {
    public static void main(String[] args) {
        // 1) 예외 종류별 catch
        try {
            Class.forName("abc.Def");                 // ClassNotFoundException
            new FileInputStream("Hello.java");        // FileNotFoundException
            DriverManager.getConnection("Hello");     // SQLException
        } catch (ClassNotFoundException e) {
            System.out.printf("클래스를 찾을 수 없습니다: %s%n", e.getMessage());
        } catch (FileNotFoundException e) {
            System.out.printf("파일을 찾을 수 없습니다: %s%n", e.getMessage());
        } catch (SQLException e) {
            System.out.printf("DB 접속 실패: %s%n", e.getMessage());
        }

        // 2) | 로 묶기
        try {
            Class.forName("abc.Def");
            new FileInputStream("Hello.java");
            DriverManager.getConnection("Hello");
        } catch (ClassNotFoundException | FileNotFoundException e) {
            System.out.printf("자원을 찾을 수 없습니다: %s%n", e.getMessage());
        } catch (SQLException e) {
            System.out.printf("DB 접속 실패: %s%n", e.getMessage());
        }

        // 3) SQLException 이 나는 경우
        try {
            DriverManager.getConnection("Hello");
        } catch (SQLException e) {
            System.out.printf("DB 접속 실패: %s%n", e.getMessage());
        }
        System.out.println("프로그램 정상 종료");
    }
}
/* 출력
클래스를 찾을 수 없습니다: abc.Def
자원을 찾을 수 없습니다: abc.Def
DB 접속 실패: No suitable driver found for Hello
프로그램 정상 종료
*/
```

- 첫 줄에서 예외가 나면 try의 나머지 줄은 실행되지 않음
- `|` 로 상속 관계인 예외를 묶으면 컴파일 오류

```java
catch (FileNotFoundException | IOException e)
// error: Alternatives in a multi-catch statement cannot be related by subclassing
```

### 계층을 이루는 예외의 처리

- `FileNotFoundException` 은 `IOException` 의 자식 → 자식을 먼저 catch

```java
import java.io.*;

public class HierarchyException {
    public static void main(String[] args) {
        String src = "./none.txt";
        try (FileInputStream input = new FileInputStream(src)) {
            int readData;
            while ((readData = input.read()) != -1) {
                System.out.print((char) readData);
            }
        } catch (FileNotFoundException e) {      // 자식 먼저
            System.out.printf("읽으려는 파일이 없습니다: %s%n", e.getMessage());
        } catch (IOException e) {                // 조상 나중
            System.out.printf("파일 읽기에 실패했습니다: %s%n", e.getMessage());
        }
        System.out.println("파일 읽음 완료!");
    }
}
/* 출력 (메시지 괄호 안은 OS마다 다름)
읽으려는 파일이 없습니다: ./none.txt (No such file or directory)
파일 읽음 완료!
*/
```

> 교재 예제는 이 지점에서 일반 `try` 를 쓰고 스트림을 닫지 않는다. 위 코드는 뒤에서 배우는 try-with-resources로 닫기까지 넣은 것.
