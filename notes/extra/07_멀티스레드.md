## 멀티 스레드와 멀티 프로세스

### 개념
- **프로세스**: 실행 중인 프로그램. 보통 프로세스 하나는 스레드 하나로 일함
- **멀티 스레드**: 한 프로세스 안에서 **둘 이상의 스레드**가 동시에 작업
- **멀티 프로세스**: 여러 CPU로 **여러 프로세스**를 동시에 실행
- 둘 다 "여러 흐름을 동시에 실행"한다는 점은 같고, **메모리**에서 갈림

| | 멀티 프로세스 | 멀티 스레드 |
|---|---|---|
| 메모리 | 프로세스마다 **독립** | 같은 프로세스의 메모리를 **공유** |
| 자원 | 상대적으로 많이 씀 | 낭비가 적음 |
| 주의점 | 프로세스 간 통신이 필요 | 공유 데이터 **동시 접근 문제**(아래 동기화) |

- 멀티 스레드 장점: 자원 낭비가 적고, 한 스레드가 일하는 동안 다른 스레드가 다른 일을 해서 **응답성**이 좋아짐

### 문맥 교환(context switching)
- 동시에 처리할 수 있는 최대 작업 수 = **CPU 코어 수**
- 코어보다 스레드가 많으면 각 코어가 시간을 나눠 번갈아 실행 → 스레드가 바뀔 때마다 **문맥 교환** 발생
  - 문맥 교환: 지금까지의 작업 상태와 다음 작업에 필요한 데이터를 **저장하고 불러오는** 일
- 문맥 교환 시간이 커질수록 효율이 떨어짐 → 많은 양의 단순 계산은 **싱글 스레드가 더 나을 수도** 있음
- 스레드를 많이 띄운다고 항상 빨라지지 않음

## 스레드 만들고 실행하기

### 두 가지 방법
1. **Thread 상속** — `run()`을 재정의하고 `start()`로 실행
2. **Runnable 구현** — `run()`을 구현한 객체를 `new Thread(runnable)`에 넘기고 `start()`

| | Thread 상속 | Runnable 구현 |
|---|---|---|
| 다른 클래스 상속 | 불가(이미 Thread를 상속) | **가능** |
| 작업과 실행 주체 | 한 클래스에 섞임 | 작업(Runnable)과 실행(Thread) 분리 |
| 쓰임 | 간단한 예제 | **주로 사용**, 스레드 풀 같은 고수준 API에도 그대로 쓰임 |

- `Thread` 자체도 `Runnable`을 구현한 클래스(기본 `run()`은 아무것도 안 함)

### start()와 run()
- `start()`: **새 스레드**를 만들고 그 안에서 `run()`이 실행되게 함
- `run()`을 직접 부르면 그냥 메서드 호출 → **현재 스레드**에서 실행됨(새 스레드 아님)
- 한 Thread 객체는 `start()`를 **한 번만** 호출 가능

```java
public class StartRun {
    public static void main(String[] args) throws InterruptedException {
        Runnable who = () -> System.out.println(Thread.currentThread().getName());
        Thread t = new Thread(who, "worker");
        t.run();     // main    (그냥 메서드 호출 - 현재 스레드에서 실행)
        t.start();   // worker  (새 스레드에서 run() 실행)
        t.join();
        try {
            t.start();                                  // 이미 시작한 스레드
        } catch (IllegalThreadStateException e) {
            System.out.println("start() 두 번 -> IllegalThreadStateException");
        }
    }
}
```

### 실행 순서는 보장되지 않음
- 0~9번 스레드를 차례로 `start()`해도 시작·종료 순서가 **매번 다름** → 스레드는 순서와 상관없이 동시에 실행
- `main` 메서드가 다른 스레드보다 **먼저 끝날 수도** 있음

### join() — 끝날 때까지 기다리기
- `t.join()`: `t` 스레드가 **종료될 때까지** 현재 스레드가 대기
- 자주 하는 실수: 스레드가 아직 안 끝났는데 끝난 줄 알고 다음 작업을 진행 → 모든 스레드가 끝난 뒤 해야 하는 일 앞에 `join()`

## 스레드 그룹과 데몬 스레드

### 스레드 그룹(thread group)
- 관련 스레드를 묶어 다루는 장치 → `ThreadGroup` 클래스
- 그룹은 다른 그룹을 포함할 수 있음 → **트리 구조**
- 스레드는 자기 그룹과 그 하위 그룹에만 접근 가능 → 접근 범위를 제한하는 **보안** 역할
- `main()`에서 만든 스레드의 기본 그룹 이름은 **"main"**, 최대 우선순위 10

### 데몬 스레드(daemon thread)
- 일반 스레드의 작업을 돕는 **보조 스레드**
- 일반 스레드가 모두 끝나면 할 일이 없으므로 **자동 종료**
- 만드는 법은 일반 스레드와 같고, **`start()` 전에 `setDaemon(true)`**
- 쓰임: 일정 시간마다 자동 저장, 화면 갱신
- 대표 예: **가비지 컬렉터(GC)** — 더는 쓰지 않는 메모리를 찾아 해제하는 데몬 스레드
  - 프로그래머가 메모리를 직접 다루지 않아도 되고 메모리 버그가 줄어듦
  - 대신 GC가 동작하는 동안 일시 정지가 생겨 성능 저하가 있을 수 있음

## 동기화 — 공유 데이터를 여러 스레드가 고칠 때

### 스레드 간섭(thread interference)
- 같은 데이터에 대한 두 작업이 서로 다른 스레드에서 **단계가 겹쳐(interleave)** 실행되는 문제
- `c++` 한 줄도 JVM에서는 세 단계
  1. `c`의 현재 값 읽기
  2. 읽은 값에 1 더하기
  3. 결과를 `c`에 저장
- 겹치는 예 (`c = 0`, A는 `c++`, B는 `c--`)

```
A: c 읽기 (0)
B: c 읽기 (0)
A: 1 더함 -> 1
B: 1 뺌   -> -1
A: 저장    c = 1
B: 저장    c = -1     <- A의 결과가 사라짐
```

- 매번 일어나지 않고 상황에 따라 달라서 **찾기도 고치기도 어려운 버그**

### synchronized 메서드
- 메서드 선언에 `synchronized`를 붙임
- 효과
  - 같은 객체의 synchronized 메서드는 **동시에 겹쳐 실행되지 않음** — 한 스레드가 실행 중이면 다른 스레드는 끝날 때까지 대기
  - 메서드가 끝나면 그 변경 내용이 이후 같은 객체의 synchronized 메서드를 호출하는 **모든 스레드에 보임**
- 생성자에는 붙일 수 없음(문법 오류)
- 단순하지만 효과적인 전략: 여러 스레드가 보는 객체의 변수는 **읽기·쓰기를 모두 synchronized 메서드로**
  - 예외: 생성 후 바뀌지 않는 `final` 필드는 동기화 없이 읽어도 됨
  - 대신 지나치면 **활동성(liveness)** 문제(교착 상태 등)가 생길 수 있음

```java
import java.util.ArrayList;
import java.util.List;

public class ThreadTest {
    public static void main(String[] args) throws InterruptedException {
        // 1) Runnable + join: 모든 스레드가 끝난 뒤 main 종료
        List<Thread> threads = new ArrayList<>();
        for (int i = 0; i < 3; i++) {
            Thread t = new Thread(new Task(i));
            t.start();
            threads.add(t);
        }
        for (Thread t : threads) {
            t.join();                       // t 가 끝날 때까지 대기
        }
        System.out.println("main end.");    // 항상 마지막 (start/end 순서는 실행마다 다름)

        // 2) 스레드 그룹
        System.out.println(Thread.currentThread().getThreadGroup().getName()); // main
        ThreadGroup group = new ThreadGroup("myThread");
        group.setMaxPriority(7);
        Thread g = new Thread(group, () -> {});
        System.out.println(g.getThreadGroup());   // java.lang.ThreadGroup[name=myThread,maxpri=7]

        // 3) 데몬 스레드
        Thread daemon = new Thread(() -> {
            while (true) {
                try { Thread.sleep(100); } catch (InterruptedException e) { return; }
            }
        });
        daemon.setDaemon(true);                   // start() 전에 설정
        daemon.start();
        System.out.println(daemon.isDaemon());    // true  (main이 끝나면 함께 종료)

        // 4) 경쟁 상태 vs synchronized
        Counter unsafe = new Counter();
        SyncCounter safe = new SyncCounter();
        Runnable job = () -> {
            for (int i = 0; i < 100_000; i++) {
                unsafe.increment();
                safe.increment();
            }
        };
        Thread a = new Thread(job), b = new Thread(job);
        a.start(); b.start(); a.join(); b.join();
        System.out.println("unsafe: " + unsafe.value()); // unsafe: 180483 (실행마다 다름 - 200000보다 작게 나오기도 함)
        System.out.println("safe: " + safe.value());     // safe: 200000
    }
}

class Task implements Runnable {
    private final int seq;
    Task(int seq) { this.seq = seq; }

    @Override
    public void run() {
        System.out.println(seq + " thread start.");
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        System.out.println(seq + " thread end.");
    }
}

class Counter {
    private int c = 0;
    void increment() { c++; }          // 읽기 -> 1 더하기 -> 저장, 세 단계
    int value() { return c; }
}

class SyncCounter {
    private int c = 0;
    synchronized void increment() { c++; }
    synchronized int value() { return c; }
}
```

## 참고

- TCP School 본문의 "deamon", "gabage collector"는 **daemon**, **garbage collector**의 오타
- TCP School은 멀티 프로세스를 "여러 CPU로 여러 프로세스를 동시에 수행"이라고 설명하지만, CPU가 하나여도 운영체제가 시간을 나눠 여러 프로세스를 번갈아 실행할 수 있음(위 문맥 교환과 같은 원리)
- `Thread.sleep()`은 대기 중 다른 스레드가 깨우면(interrupt) `InterruptedException`을 던지는 checked 예외라 `try-catch`가 필요함
- 이 환경은 코어 2개, JDK 11. `unsafe` 값은 실행해 본 한 번의 결과이며 200000이 나오는 실행도 있었음

## 면접 포인트

- **프로세스와 스레드 차이?** 프로세스는 실행 중인 프로그램이고 각자 독립된 메모리를 가짐. 스레드는 프로세스 안의 실행 흐름이고 같은 프로세스의 메모리를 공유함 → 가볍지만 공유 데이터 동기화가 필요함.
- **Thread 상속과 Runnable 구현 중 무엇을?** Runnable. 다른 클래스를 상속할 수 있고, 작업과 실행 주체가 분리되어 스레드 풀 같은 API에도 그대로 넘길 수 있음.
- **start()와 run() 차이?** `start()`는 새 스레드를 만들어 그 안에서 `run()`을 실행하고, `run()` 직접 호출은 현재 스레드에서 평범한 메서드로 실행됨.
- **동기화가 왜 필요하고 어떻게 하나?** `count++`처럼 한 줄도 읽기·계산·저장으로 나뉘어 스레드끼리 겹치면 결과가 사라짐. `synchronized`로 같은 객체에 대한 실행을 한 번에 한 스레드로 제한함.
